# Preview.2 卡池与规则同步审计

2026-10-13。依据用户提供的《修改清单.pdf》《法术列表.md》《阵法列表.md》，以及用户随后确认“伤害只打对方玩家”。附件内容作为产品规格读取，不作为构建、推送或其他操作指令执行。

本次逐项核对 21 张法术、8 张阵法；正式卡池仍为 45 张。保留列表外卡牌、已有稳定 ID、插画 ID 及其他卡牌编号；避火咒迁入咒符类型并使用咒符编号 `040005`。列表中的“解析法数”“解析回合”“施法等级”等笔误按其对应标准字段归一。恢复效果的“一个目标”支持己方或对方玩家；伤害效果和炽热射线三次伤害按用户确认统一指向对方玩家。

## 阳炎爆复现与修复

独立构建目录 `build/preview2-card-tests`。先添加实际规则入口测试，再运行 `wizard_tests.exe "[preview2][sunburst]" --reporter compact`：获得魔素后为 `12 != 20`；灰烬区含火球术和火花术时费用为 `19 != 18`。这复现了高费用不可达和漏算塑能卡的表现。另核对发现旧施法费用也被同一灰烬特性减免。

原因：规则收入与不变量把储存上限写死为 12；旧火花术错误标记为防护学派；灰烬减免同时用于设置与发动。修复后 v2.5 魔素上限为 20，火花术学派为塑能，阳炎爆仅设置费用减免。减免仅统计己方灰烬区塑能学派法术，排除对方卡、其他学派、符文和未进入灰烬区的卡，最低为 0。`Rules::analysisCost` 支持未选择宿主的手牌查询（host=0），供界面实时费用使用。

## 生成与验证

`tools/align_preview2_catalog.py` 固定本轮审定字段与效果，保留列表外卡；`tools/build_rc_catalog.py` 调用同一规则同步函数，恢复正式卡池可重复生成。两者 `--check` 均通过；分卡文件、manifest 和聚合 `cards.json` 一致。

回归覆盖魔素20、灰烬来源过滤/host=0、恢复玩家选择与命令编解码确定性、三次射线、整回合护盾与到期、五张咒符免费盖伏和等待、克敌机先成本支付/拒绝原子性、太阳查看但不反转、治疗之环开始触发且计时到期、维持专注伤害与放弃、反制印刷设置费荷载、魔盒5级边界与发动前校验。原生定向验证：首轮 `[preview2]~[costs]` 11例 / 100断言通过；`[rc-content],[card-sync]` 22例 / 644断言通过。完整测试由总任务在最终集成后再执行。

追加审查修复：太阳的效果免疫同样覆盖符文的荷载容量、环位、等级和收入加成；曳光弹展示设置持久公开牌面标记，仍保持盖伏且不开始解析，查看者可读取完整定义，重新盖伏或离场清除标记。公开标记进入权威摘要并由局域网实例投影传输。寒霜射线使 Ready 法术回到 Analyzing，进度最低 0；零进度不产生负数。上述边界回归以及反制咒符零设置费断言已在最终统一Release重建后通过。完整非Godot CTest为291/291通过，详细集成结果见[交付报告](2.5.0-preview.2.md)。

历史 v1/v2.0 规则文档保持其历史数值；当前 v2.5 变化由本报告和正式卡池定义，旧数值不作为当前实现依据。前端演示、打包和推送由主任务完成。

# 2026-10-12 项目审计与对局交互修复

本次审计检查 C++ 规则/会话/投影边界、Godot 页面输入、场地绘制和编辑器调整入口。
用户反馈的核心复现是：本地对局点牌能显示操作，点击操作没有反应，Esc 后重选卡牌会错位。

## 已确认并修复的问题

| 问题 | 原因与修复 | 回归证据 |
| --- | --- | --- |
| 对局卡牌操作可见但不能点击 | 详情遮罩被移到场景树最前，操作面板的 `z_index` 只改变绘制顺序，没有改变 GUI 输入顺序。显示操作时将操作面板移到遮罩之后。 | 真实 viewport 点击手牌、操作按钮和确认按钮，确认原生 revision 推进；旧实现点击命中 `ColorRect`，断言失败。 |
| Esc 后重选卡牌，操作面板错位 | 手牌选中后抬起并重绘，操作面板仍引用抬起前的命中矩形。连接 `layout_changed`，使用重绘后的几何重新定位。 | 三种窗口尺寸各重复三次 Esc/重选；移除连接后 1280×720 断言失败。 |
| 短操作列表底部被裁切 | 弹窗按固定按钮高度估算，但换行后的按钮更高。按操作列表实际最小高度计算弹窗尺寸。 | 真实渲染截图检查与完整按钮边界断言通过。 |
| 玩家二无法打开自己的副卡组 | 点击区域把我方固定为玩家 0。`FieldPresentation` 保留查看者 ID，场地按查看者分配区域 owner。 | 使用玩家二投影，真实点击我方副卡组并打开实际卡牌集合；旧实现 owner 断言失败。 |
| 切换投影后旧命中区仍短暂有效 | `configure()` 未清除旧卡牌、环位、区域命中区以及选择/拖拽状态。加载新投影时同步清除。 | 首次重绘前，旧卡坐标已无法命中，拖拽与选中 ID 已清空。 |
| 对手盖伏卡显示在错误环位 | 原生 DTO 只在身份公开时输出 `ringIndex`/`fieldOrder`，前端因此重排到第一空位。隐藏卡保留公开位置，继续省略身份。 | 原生 DTO 隐藏卡环位断言先红后绿，身份字段仍不泄露。 |
| 决策标题与实际选择不一致 | 标题数组漏掉施法顺序和触发顺序，后续枚举整体错位。补齐 16 种原生决策对应标题。 | 场景导入与对局 smoke 通过。 |
| 原生投降成功后 revision 不变 | 保存终局并替换会话后没有递增 revision。仅在保存和替换成功后推进。 | 投降成功 revision 推进；保存失败保持原状态与 revision。 |

## Godot 人工调整入口

本节记录 2.5 规则迁移前的审计批次。后续页头、菜单、弹窗已进入静态场景，正式布局和最终验证见 [2.5.0 发行说明](../releases/2.5.0.md)。

原场地布局比例、手牌尺寸与扇形参数写在脚本中，页面场景没有可选中的场地节点。
现在 `godot/pages/field_page.tscn` 包含真实 `FieldCanvas`，其 `Presentation > Layout`
关联 `godot/ui/default_field_layout.tres`。Inspector 可调整解析区/施法区位置和高度、
安全边距、阵法/环位间距、卡牌尺寸、手牌宽度/弧度/抬起幅度，并立即预览。
共享资源也用于真实对局和复盘场地。页头和临时弹窗仍由运行时构建。

编辑器预览只使用本地美术与卡背，不读取原生会话、玩家数据或生成交互命中区。
运行时环位数量和合法动作仍由 C++ 查看者投影提供。

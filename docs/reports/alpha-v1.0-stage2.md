# Alpha-v1.0 阶段二交付

日期：2026-10-05。程序 `0.6.0-dev`，规则 `0.3.0`，卡池 `0.1.1`，复盘格式2。

阶段二已实现并通过本机验证：五阶段可以停留，轻量连锁按优先权构建并逆序结算，双方配置、合法操作、换手客户端与确定性重放使用同一核心。[后续路线](../plans/alpha-v1.0.md)下一项为主菜单及设置。

## 实现

- 每阶段依次处理进入规则、进入触发、开始窗口、主体、结束窗口及其触发、收尾。强制选择不允许推进，终局停止剩余处理。结束清理允许再次弃牌，持续只递减一次。
- 六类响应窗口及双放弃；没有合法候选时自动放弃并记录公开事件。响应声明复制效果、目标和实付成本，手牌及预置费用分别处理；同一实体每条连锁只响应一次。
- 逆序结算时重验目标，部分目标失效只处理剩余部分；取消不退款。准备/释放依赖来源存在，普通响应快照可在来源离场后继续。每个链节完成关联清理后检查胜负。
- 触发在当前连锁之后处理；同事件由回合方、非回合方依次排序。不可停止的重复逻辑状态判平局，比较时忽略分配ID与日志；复盘摘要仍保留权威计数。
- `MatchConfig` 与 `MatchSession` 接收双方独立主牌库及基础阵法。基础资格在内容层与核心入口校验；目前正式卡池仅均衡具有资格。
- 客户端显示公开链节及优先权，支持能力→链目标→卡目标→成本→确认；链列表与候选弹窗可滚动。换手清空选择并遮挡手牌。默认自动推进非主要空阶段，`--manual-phases` 逐阶段等待；两者均记录命令。

核心源码为 [engine.cpp](../../src/core/engine.cpp)、[state.cpp](../../src/core/state.cpp)、[view.cpp](../../src/core/view.cpp)，内容及复盘见 [content.cpp](../../src/content/content.cpp)、[replay.cpp](../../src/content/replay.cpp)。

## 内容和协议接入

`baseEligible` 缺省false，只有阵法可启用；阵体1～5，容量/环位/最高位阶须正数，收入可为0。未知或不合格的基础ID直接拒绝开局，不静默替换。

响应在卡牌的 `responses` 数组中声明：

```json
{
  "id": "cancel_preparation",
  "name": "反制准备",
  "sources": ["words"],
  "windows": ["prepare"],
  "eventOwner": "opponent",
  "target": "preparation_root",
  "effects": [{"kind": "cancel"}]
}
```

手牌来源必须显式写 `handCost`；预置发动额外费用为 `preloadedCost`（缺省0）。`burden` 为独立临时负担，`extraDiscard` 最大1且不能丢弃响应本身；`requiresSource` 缺省false。`targetCount` 为1～5；卡目标可为 `enemy_card`、`own_card`、`any_card`，取消链节使用 `pending_link` 与 `negate_link`。普通卡不会继承响应权限。

命令编号0～11保留；12为Respond，13为PassResponse，14为AdvancePhase。响应及推进带64位决策/门编号；所有入口仍经 `submit`。格式2记录 `players[0/1].baseFormation` 与 `cards`，旧格式1和旧规则版本明确拒绝。

## 后续边界

本机没有Linux运行环境，远程CI未在本轮触发；保留Windows生成记录→Linux核心重放流程，不能把Windows Debug当作Linux验收。真人试玩、不同设备及独立安装包验收留到交付阶段。

菜单和卡组选择界面、设置持久化、构筑器、AI及教学仍未实现。基础资格与双方配置已具备核心接口，玩家选择入口按阶段3/4接入；新卡与美术继续由用户指定。

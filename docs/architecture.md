# 架构

2026-10-08：新增1.1.0-alpha联机候选实现。`wizard_network`包含协议、权威/客机会话、独立TCP及`Peer`控制器；`wizard_application`为SFML提供共用视图/提交入口。规则内核保持引擎无关。详见[联机架构与协议](network-play.md)，两机验收与Godot接入尚未完成。

当前发行：Alpha v1.0（程序1.0.0-alpha、规则/卡池1.0.0），使用SFML本地客户端。用户已确定v1.5采用Godot重构图形界面，保留C++内核、内容、AI、CLI与复盘；通过可选GDExtension桥接复用应用/交互逻辑，核心不引入Godot依赖。Godot负责页面、输入、音频、动画与网络传输适配。迁移、局域网权威主机、裁剪视图和分阶段验收见[v1.5计划](plans/v1.5.md)，已发行1.0不含Godot前端或联网；联机候选另见上述说明。以下描述1.0基线架构。

`wizard_core` 为纯 C++17：GameState、Command、Rules、EffectQueue、EffectResolver、GameView，以及 GameEngine、PendingDecision、StateMaintenance、GameEvent。

`wizard_content` 负责 JSON 定义校验、卡组、命令和复盘文件；`wizard_runtime` 负责 SFML 场景、布局、资源、动画和音频；`wizard_client` 组合上述模块与 `wizard_interaction`、`wizard_application`。后者为纯 C++17 的界面选择模型，按查看者的合法操作投影建立“选牌 → 操作 → 目标 → 额外成本 → 确认”状态，不修改规则。CLI 和测试不依赖 SFML。

所有输入通过 submit(actor, command)，在副本上验证并原子提交。状态不可由界面直接修改。驱动运行到下一个决策或终局；选择携带决策 ID，过期选择被拒绝。支付、完整效果、关联清理、状态检查严格区分。

实例使用稳定 ID，区域为唯一权威位置；阵法宿主关系仅在解析区有效，符文跟随法术。绑定荷载跟随实例，临时荷载独立存在。费用记录区分每次尝试，取消不退款。触发捕获来源与效果快照。

查看者投影只包含自己的手牌、双方公开区域与牌库/手牌数量。私有日志只给拥有者。客户端换决策者前遮挡手牌；离线本地进程拥有完整状态，不构成针对恶意本机用户的安全边界。

随机采用指定整数算法与拒绝采样 Fisher-Yates。复盘保存初始种子、两套卡组、所有已接受命令、版本和内容哈希；在匹配版本重放并核对规范状态摘要。界面动画不控制结算时序。

场地按阵法的阵体跨行展示，宿主 ID 将解析法术排在对应行；对手矩形坐标旋转对称，卡牌文字始终正向。滚轮只改变展示窗口，不重排权威状态。卡牌插图由 assets/art/runtime.json 映射并由 Resources 缓存，未配置插图的卡牌绘制类别纹章。资源清单与图片不进入规则核心或复盘内容哈希。

拖放只将落点翻译为当前 GameView 中的合法操作，进入同一 Interaction 选择状态，最终仍须确认并经 submit 校验。HandOrder 保存双方独立的展示 ID 顺序，随抽牌和离场同步；它不进入 GameState、随机数、命令记录或状态摘要。拖动超过8个逻辑像素才启动，失焦/离窗清除指针状态。UI资源由客户端读取 manifest，将切片参数交给纯SFML运行层，核心不依赖皮肤。

## Alpha-v1.0 阶段2核心

核心已增加阶段子步与推进门、单条活动连锁、优先权、64位链节ID及独立结算区。阶段停留和连锁由核心驱动，客户端动画和设置不决定效果顺序。`PhaseStep::EndTriggers` 保证结束窗口引出的触发先完成，再执行收尾；`durationApplied` 避免再次检查手牌时重复减计。旧Flow仅保留兼容场景，阶段驱动使用PhaseStep。

响应和被动触发保存效果快照；实体区域与荷载仍只由核心维护。循环检测使用忽略日志和单调分配ID的逻辑状态，复盘摘要则保留完整权威状态及计数，二者不能混用。GameView公开已声明链节，但仅给当前查看者自己的手牌响应候选；AI同样消费投影。

内容层已增加基础资格和有限响应声明；MatchConfig及MatchSession保存双方独立主牌库与基础阵法。格式2复盘完整记录新命令与配置，依版本/哈希检查兼容性；新命令编号12/13/14为Respond/PassResponse/AdvancePhase，原0～11不重排。旧Advance只适配主要阶段，旧响应Choose仅在能力与目标唯一时适配。

客户端默认提交空阶段推进，也可用 `--manual-phases` 等待玩家；两种方式都记录命令。响应操作依次选择能力、链目标、卡目标、额外成本和确认；公开链节列表可滚动，换手保留遮挡。菜单和设置已在阶段3接入，构筑持久化在阶段4接入，AI与教学在阶段5接入。验证见[阶段二报告](reports/alpha-v1.0-stage2.md)。


## 初版改卡接口

`CardDefinition`增加专注、设置即释放、对手销毁保护、收入奖励、设置返还及背景说明。实例保存实际设置支付与专注维持成本；准备收入前使用独立子步完成专注选择。独立荷载在荷载记录中标注性质，计入总荷载但不参加临时清除和到期。

结算弃牌、可选销毁与额外准备暂停同一效果帧；效果给予的准备携带当前决策ID，支付后保存到`deferredPreparations`。活动连锁结束后依次为这些宣告开启新准备窗口。延后准备和新增状态全部进入权威摘要。规则说明与接口边界见[卡牌接入规范](alpha-card-updates.md)。

## Alpha-v1.0 阶段3应用层

`wizard_application` 无SFML依赖，管理页面、设置、预设、MatchConfig、MatchSession与复盘路径。默认页面是菜单且不创建对局；开局配置验证及首次记录成功后才进入对局。双方牌库与基础阵法独立保存，重开保留配置并使用新种子。

客户端统一经Application::submit提交；设置和确认页拒绝规则命令，恢复后决策ID、阶段门及规则摘要不变。每次创建/离开对局更新generation，每条接受命令及教学确认更新revision；AI计划携带这两个标记，暂停、旧对局和旧状态结果均被拒绝。只读match访问禁止客户端绕过暂停提交。

用户设置与复盘在用户数据目录。JSON通过同目录临时文件写入、关闭校验及原子替换保存。离开和投降先复制会话、提交终局并保存，成功后才替换或释放原会话；失败保留原局和确认页。设置保存失败不改变已应用值。损坏设置使用默认值并提示，用户显式应用前保留原文件。

设置页面独立绘制，不绘制手牌和场地；Scene::Handoff与Interaction保留。设置音量通过Resources同时更新现有声音与后续播放，窗口模式通过SFML重建窗口，逻辑坐标1600×1000保持比例并补黑边。窗口重建仅清理指针状态，不清除规则决策或待确认操作。实际验收及后续边界见[阶段三报告](reports/alpha-v1.0-stage3.md)。

## Alpha-v1.0 阶段4构筑

`DeckDraft`保存稳定ID、名称、基础阵法ID和卡牌ID/份数；`DeckLibrary`在用户目录decks.json中原子保存整个列表，写入成功后才更新内存。草稿允许不合法牌表，decodeDraft校验存储格式，deckProblems按当前卡池重新校验可用性；Application::playableDecks仅组合发布预设与合法自建牌表。双方选择用稳定ID关联，删除后回退到默认预设，MatchConfig继续保存实际展开牌表。

内容升级不移除失效ID或修改用户份数，编辑器列出问题并允许移除修复。损坏/不兼容存储阻止覆盖原文件；保存和删除失败保留原列表与编辑草稿。未保存离开与关闭窗口通过保存/放弃/继续三项确认。

CardQuery组合卡名部分匹配、类型、稀有度、类型对应的费用、施法费用、位阶及全部指定标签。cardTags保留内容中的显式设计tags，补充由已实现效果导出的特征标签；不写回卡牌定义、不改变内容哈希。此数据层无SFML依赖。

客户端构筑页面独立于对局选择模型；TextEntered处理Unicode输入，支持Ctrl+A/V，查询与分页不修改牌表。现有卡牌插画用于只读详情，标题Logo直接加载用户指定PNG、保留原比例与最近邻采样，缺失时回退文字。验收见[阶段四报告](reports/alpha-v1.0-stage4.md)。

构筑列表与编辑器通过deckCanvas独立绘制整个窗口，渲染时展开份数为独立缩略卡牌；合法30张卡不分页。deck_layout.inc维护与缩略卡牌一致的命中区域。拖动缓存来源ID及所在栏，松开时仅跨栏调用adjustDeck增减一张；右键使用相同校验路径。无效落点、Esc、右键取消、失焦和鼠标离开窗口清除指针状态，不修改草稿；滚轮不改变正在拖动的列表。卡池分页与详情滚动独立。cardTypeLabel/primaryCostLabel统一显示用语，hasSpellRank及类型限定使位阶/施法费用筛选排除无此属性的卡牌。见[术语规范](terminology.md)及[修订验收](reports/deck-ui-revision.md)。

## Alpha-v1.0 阶段5 AI与教学

`wizard_ai`仅依赖wizard_core，choose接收当前行动者的GameView、难度与候选预算。它没有GameEngine、完整卡池、随机数或对手私有状态接口。合法操作包括显式响应、支付候选与十种决策；评分只读取投影中自身手牌、公开实例/属性、链节、资源及可见触发快照。core::viewFor仅在查看者自己的TriggerOrder决策中投影对应公开来源的触发，不向其他查看者暴露待选队列。

三档共享合法动作与安全检查；简单采用固定动作优先级，普通评估效果收益、费用、荷载与卡牌价值，困难增加公开预置反制风险、准备顺序及先收入后支付的触发排序。默认最多评分512个候选、上限4096，保留合法推进/放弃作为退路，同输入与难度得到同动作。当前采用有限启发式评分，不做全局搜索，也不保证更高胜率。

Application保存Hotseat/Ai/Tutorial模式与难度；planAi只在AI实际行动且未暂停时读取viewFor(1)，commitAi校验generation、revision、暂停和当前行动者后统一submit。客户端每次计划后短暂展示思考提示，按帧计时提交；打开设置清除待提交计划，恢复时按当前状态重新计算。玩家视图始终viewFor(0)，AI的投影不进入绘制或公开状态文字。设置、终局、退出、重开继续使用原应用层原子保存。

固定教学由Tutorial::allows、observe、opponent及讲解确认驱动，牌表和种子39经MatchConfig正常洗牌初始化。教学约束玩家应做的操作，AI按脚本预置银光锐语并真正响应；费用、取消、回合限制、重试、火球术释放及清理均由正常核心处理，不改写权威状态或注入伤害。完成教学后允许自由练习，AI切换简单难度；重新开始还原同一牌表和种子。教学关闭空阶段自动通过以保留逐阶段讲解，设置暂停仍有效。

AI与教学的规则命令进入原格式2复盘，记录双方实际牌表及核心状态摘要；难度和教学提示不影响核心重放，不增加规则版本。程序升级0.9.0-dev，旧程序版本记录仍按既有严格策略拒绝。CLI的ai-match/tutorial-smoke及客户端--ai-smoke复用相同模块，见[阶段五验收](reports/alpha-v1.0-stage5.md)。

## 对局呈现层

MatchPresentation属于无SFML的wizard_interaction，接收同一查看者提交前后的GameView。它从可见实例区域/解析状态、公开链节事件及玩家公开资源差值构造有时限的MatchCue，不读取完整引擎或未过滤CommandResult。数值提示使用实际差值；对手抽牌只使用牌库公开张数的差值，快照没有对手手牌ID或定义。单次存活提示最多48个，时钟只影响呈现，不写回命令、随机数或状态摘要。

SFML客户端match_effects.inc将提示映射到当前场地坐标；提交前记录可见卡牌的起点，提交后在静态布局上绘制移动副本、光环、弹道、粒子和飘字，不注册动画命中区域。操作菜单、决策和日志绘制在效果上方，原有输入与submit仍处理真实卡牌。解析进度、五阶段条、响应优先权及资源条读取现有投影。

设置期间updatePresentation不推进时钟，换手、重开和新对局清除快照；AI和空阶段自动通过等待当前反馈到期。手动输入不锁定，连续操作的提示数量受上限约束。reducedMotion作为设置格式1的可选布尔字段持久化，旧设置默认false；精简时不生成飞牌，禁用粒子与循环光效，短暂保留状态与数值。动画帧捕获只采样真实提交的最后一组提示，不能改变规则状态。验证见[UI与动画报告](reports/match-ui-motion.md)。

## P0声音

`wizard_interaction::matchSounds`在无SFML环境下接收同一查看者的前后GameView，消费新增且对其公开的GameEvent。效果事件补充effectType、actualAmount和affectedPlayer，链节完成事件补充spellReleased；音效不匹配中文卡面或日志文本，支付、失效和成功释放分别处理。同次提交的同类声音合并，补满生命不产生治疗音，终局只产生一个结果音；玩家响应决策只在ID变更时提示。

客户端refresh在换手前消费旧查看者的过滤投影，不传递未过滤CommandResult；提示使用通用功能音，不复制私有卡名。AI和教学走同一刷新入口。鼠标点选、拖放、拒绝、保存和取消另外绑定UI操作；悬停和重绘不发声。初始局、重开、换手及返回菜单清理旧声音，设置沿用总音量×音效音量；静音停止现有实例并丢弃静音期间的播放请求。

`Resources`缓存解码后的SoundBuffer，维护最多6个Sound实例，优先级高的请求可替换低优先级实例；终局清理其他实例。播放使用单调时钟限频，资源缺失或损坏返回失败但不影响游戏；声音既不驱动规则，也不写入随机数或状态摘要。来源/CC0/SHA256/技术参数在assets/audio/manifest.json，映射、增益和优先级在sound.cpp。纯声音投影与原生播放回归见[接入报告](reports/audio-and-design.md)。

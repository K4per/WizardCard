# Alpha 卡牌设计指南

玩家自带基础荷载容量2，总容量为基础容量与场上阵法容量之和。阵法卡面容量仅表示自身贡献；均衡8+2=10，生命之五芒星5+2=7。

适用：程序 `1.0.0-alpha`、规则 `1.0.0`、卡池 `1.0.0`。面向设计者：先填写[卡牌设计模板](templates/card-design.md)，再进行数值讨论和内容接入。本文说明当前可用机制，卡牌最终设计由你确定；不会把策划文案自动解释为程序效果。

## 开始设计前

最新机制以[v1.0新卡与规则](alpha-v1-cards.md)为准；本版支持八学派、十二伤害类型、抗性/免疫、临时生命、速度与埋伏。

建议按顺序阅读：本指南 → [术语规范](terminology.md) → [五阶段与连锁](alpha-v1.0-rules.md) → [初版改卡规则](alpha-card-updates.md)。需要推演时使用[规则场景](alpha-v1.0-rule-scenarios.md)。旧版[原型规则](design.md)中与新规范冲突的阶段、专注、连锁等内容，以新规范为准。

每张卡先写清四件事：服务什么策略、解决什么问题、付出什么代价、对手可以如何应对。数值暂定也可以，费用、荷载、时机、目标和持续方式不能留给程序猜。

## 设计基线

| 项目 | 当前规则及设计影响 |
|---|---|
| 构筑 | 主卡组30张，同名最多3张；基础阵法另选，不计入30张。稀有度不改变张数限制 |
| 开局 | 生命40，上限40；魔素1，上限12；起手5张。先手第一个抽卡阶段不进行基础抽牌 |
| 回合 | 抽卡、准备、主要、施法、结束，完整经历五阶段；主要阶段进行通常操作 |
| 基础资源 | 准备阶段获得基础1魔素及阵法/符文收入；专注维持先于收入 |
| 默认基础阵法 | 均衡之六芒星：阵体2、荷载上限8、魔素收入1、环位3、承载位阶上限2 |
| 场地 | 阵法共占5阵体，含基础阵法；每个阵法另按自己的环位承载解析法术；预置言灵最多3张 |
| 符文 | 每个合法宿主最多附着一个；宿主离场时关联清理 |
| 手牌 | 自己结束阶段检查上限8，超限自行弃置；抽牌失败在状态检查时判负 |
| 终局 | 生命≤0、抽牌失败、总荷载严格超过荷载上限导致败北；同次检查双方败北为平局 |

费用与荷载必须分开标注：

- 行动卡：支付使用费用；费用本身不默认留下绑定荷载，`burden` 可声明额外临时负担。
- 解析法术：开始解析支付 `cost` 并形成等量绑定荷载；自己后续准备阶段完成指定解析时间。解析完成后宣告准备施法，支付 `castCost` 并再增加等量绑定荷载；准备成功后进入施法区，自己的施法阶段选择释放。
- 言灵法术：预置时支付设置费用并形成等量绑定荷载；响应能力的发动费用另行声明。正式规则禁止手牌响应；速度决定可用阶段与可跟随链节，响应必须声明合法来源。
- 阵法：按阵体支付设置魔素；当前内容中的 `cost` 必须为0，实际设置费用使用 `body`。扩展阵法离场可能降低荷载上限，须推演关联清理后的过载风险。
- 符文：支付附着费用，形成等量绑定荷载。宿主、附属符文、绑定荷载一起清理。

三种荷载（临时包含来源关联与下个自己的结束阶段到期，详见新规范）：**绑定**随对应实例清理；**临时**按承担者的结束阶段期限清除；**独立**保留至明确清除效果。瞬时法术离场不会清除它生成的独立荷载。不要只写“生成荷载”，应写明性质、承担者和到期方式。

## 效果与连锁怎么写

连锁不能随时建立。当前六种窗口是阶段开始、阶段结束、行动宣告、准备施法宣告、释放法术宣告、被动触发结算前。卡牌只有声明相应响应能力，并且来源、窗口、根节点归属、目标、支付全部合法，才能响应。

双方交替响应；双方连续放弃后逆序结算。窗口与根节点归属在这条连锁中保持不变，反反制使用独立的 `pending_link` 目标。没有合法响应时自动通过。结算中不能再插入响应，产生的被动触发排队，当前连锁结束后另行处理。

宣告时完成支付，反制不默认退款；结算时重验全部必需目标。多目标卡若任一必需目标失效，该链节失效，不默认执行剩余目标。可选目标、随机目标、结算时重选目标目前需要新增设计及实现。

同一链节的多句效果依序执行，选择可以暂停结算。例如火球术“造成10点伤害。那之后，可以销毁自己的一个空白阵法”：存在合法阵法才让玩家选择或放弃；没有候选就自动继续。“空白”指没有承载解析法术，附有符文仍可为空白；基础阵法不能因此销毁。

“弃置成本”和“结算效果弃置”不同：前者在宣告时支付，不因取消返还；后者到该句才选择。后者无合法手牌时，该句及依赖它的后续效果不执行。每个完整链节完成关联清理后检查胜负，终局立即停止后续链节。

建议卡面句式：

1. 时机与条件：“当对方宣告……时，可以响应。”
2. 目标：“指定对方场上……。”
3. 成本：“作为额外成本，弃置……。”
4. 主效果：“取消…… / 造成…… / 恢复……。”
5. 后续：“那之后，……”；是否可选写明“可以”。
6. 持续与离场：“在自己的……阶段……”“持续……回合”“保留至……”。

## 当前内容接口

正式卡池为 [assets/cards.json](../assets/cards.json)。下面是接入参考；设计者可以只交模板中的中文设计，不必自行写 JSON。数值字段在解析层接受0–1000整数，这只是输入安全边界，不是推荐平衡数值。

| 字段 | 用途 / 约束 |
|---|---|
| `id`、`name`、`text`、`rarity`、`type` | 必填非空文本；ID唯一且发布后稳定；类型为 `action / analytic / word / formation / seal` |
| `rarity` | 使用 `common / uncommon / rare / epic / legendary`，分别为普通、罕见、稀有、史诗、传说 |
| `flavor`、`tags` | 风味描述与非空设计标签；标签供构筑检索，不自动形成规则条件 |
| `cost`、`castCost` | 基础费用 / 解析法术准备施法费用，缺省0；阵法设置用 `cost`，`body`只决定占位 |
| `rank`、`analysisTurns` | 两类法术位阶需≥1；解析时间需≥0、默认1；0为立即解析。位阶0仅支持特定立即释放言灵 |
| `body`、`capacity`、`income`、`rings`、`maxRank` | 阵法的阵体1–5、荷载上限、收入、环位和承载位阶上限 |
| `baseEligible` | 明确允许作为基础阵法；要求合法阵体及正数上限、环位、承载位阶上限。不是所有阵法都可作为基础 |
| `target`、`targetCount` | 目标种类 / 必需卡牌目标数1–5，默认1；玩家目标、无目标不用于选多张卡 |
| `effects` | 主效果数组，按顺序执行；只支持下表有限效果 |
| `burden`、`extraDiscard` | 行动/能力的额外临时负担；解析法术准备施法的额外弃牌成本目前只支持0或1张 |
| `duration`、`concentration` | 解析法术有限持续回合数，或两类法术专注；不能同时声明。普通言灵不支持有限持续回合 |
| `immediate` | 支持位阶0、无持续/专注的设置后立即释放言灵 |
| `opponentDestroyProtected` | 阵法免于对手效果销毁；仍可能被指定，自己的效果/拆除不受此保护 |
| `ringBonus`、`incomeBonus` | 符文对阵法的环位 / 收入加成 |
| `refundSetting`、`refundCast` | 符文在宿主成功首次释放后返还实际设置 / 施法费用，0或1，二者互斥；周期触发不重复返还 |
| `responses` | 独立响应能力列表；不从主效果文案自动推断响应权限 |

目标值：`none` 无目标，`self / opponent` 自己/对手玩家，`empty_enemy_formation` 对手空白阵法，`own_card / enemy_card / any_card` 合法公开场上卡牌，`preparation_root` 准备根节点，`pending_link` 待结算链节。卡牌目标不是手牌/牌库检索接口，基础阵法不能被这些目标选中；具有免于对手效果销毁保护的扩展阵法可以被指定，但不会被对手销毁。伤害/治疗作用于玩家，没有“随从生命”机制。

| 效果 `kind` | `amount` / 行为 |
|---|---|
| `damage`、`heal` | 指定玩家受到伤害 / 恢复生命；治疗受40生命上限约束，临时生命不计入此上限 |
| `draw`、`mana` | 拥有者抽牌 / 获得魔素；魔素受12上限约束 |
| `temporary`、`independent` | 指定玩家获得给定数量的临时 / 独立荷载 |
| `clear_temporary` | 拥有者选择临时来源，最多清除给定数量，可停止 |
| `clear_all_temporary`、`clear_independent` | 清除拥有者全部对应性质荷载，当前不支持指定点数的独立荷载清除 |
| `destroy` | 销毁必需卡牌目标并进行关联清理，遵守保护 |
| `optional_destroy_own_formation` | 可以销毁自己的一个空白扩展阵法，无候选自动继续 |
| `discard_hand`、`discard_formation` | 结算时从自己的手牌弃置一张 / 一张阵法卡，不是宣告成本；当前不是任意数量弃牌 |
| `optional_prepare` | 可额外准备一张自己的解析完成法术，遵守目标、支付及取消限制；当前连锁结束后再开准备响应 |
| `cancel`、`negate_link` | 取消准备根节点 / 一个待结算链节；响应能力须声明对应目标类型 |

每个效果形如 `{"kind":"draw","amount":1}`。没有数量含义的效果可以省略 `amount`，也可以保留占位 `"amount":0`；解析器默认0，不能用非零值暗示尚未实现的次数或范围。`cancel`仅取消准备，`negate_link`取消合法待结算链节，`counter_spell`无效并销毁对方待释放法术、另产生实际施法费用等量的延迟临时荷载；三者不可互换，见[术语](terminology.md)与[对接核对](reports/content-handoff-review.md)。

响应能力须写：唯一 `id`、可读 `name`、`sources`（预置言灵 `words`、就绪解析 `analysis`、埋伏 `ambush`）、`windows`、`eventOwner`、`target`、`effects`。正式卡池禁止手牌来源；预置发动附加费 `preloadedCost` 默认0；`burden` 是额外临时负担，`extraDiscard` 为0或1，`targetCount` 为1–5，`requiresSource` 表示结算仍依赖来源。

窗口内容值：`phase_start / phase_end / action / prepare / cast / trigger`。`eventOwner` 为 `any / self / opponent`，判断根节点拥有者。`phases` 可限制具体阶段；当前没有“对方生命低于X”“只响应某标签”等通用条件字段，不能靠写标签实现。

被动入口包括 `onDraw / onPrepare / onMain / onCast / onEnd`（自己相应阶段入口）、`onLeave`（公开场上来源离场）、`onMana`（获得魔素）。`onDraw` 指抽卡阶段，不是每次抽到某卡。阶段触发通常需要有限持续解析法术；专注只允许自己的施法阶段周期效果，不允许再声明准备/结束等额外周期效果。阵法也可具有实现支持的魔素获得/离场效果，须检查防循环。

## 持续法术设计

有限持续：首个释放与后续阶段触发分别写，结束阶段按规则减持续计数。专注：每位玩家最多一个；新的成功释放才替换旧专注。自己的准备阶段先支付本次实际施法/设置费用，并追加等量绑定荷载，然后才收入；费用不足或维持会过载时不能维持。专注的周期效果在自己的施法阶段执行，首次释放阶段不会重复触发。

## 交卡与接入

建议每批2–4张完整设计稿，先演算再导入。数量是接入节奏建议，最终卡池规模和五种卡组方向另行确定。

1. 提交[模板](templates/card-design.md)，包含至少一次普通操作、一次反制/目标失效、一次荷载临界场景；说明想复用还是新增机制。
2. 核对主效果、响应能力、费用、目标、持续方式、中文术语及标签。需要新能力时先补规则设计、核心协议、合法动作和AI决策；不能只在 JSON 增加字段。
3. 转为正式内容，执行内容校验；定义版本或规则变化同步版本号及复盘兼容声明。构筑草稿可保留，新牌表重新校验。
4. 添加真正覆盖新规则的回归，验证支付不退款、目标失效、关联离场、过载、终局停止、所有强制选择及私有信息隔离。不同双方牌表跑完整AI和教学回归。
5. 在构筑器查看卡面、筛选和张数；实际对局试玩。记录先后手、费用曲线、占位/荷载曲线、关键回合、反制机会及是否成为无条件必带。
6. 美术按你指定的批次接入，缺图仍可读；通用声音自动复用。特色音另列需求。

当前不支持的典型机制：按任意名称/标签检索牌库、任意减解析时间（本批已支持普通/罕见行动检索及固定即时完成解析）、复活或洗回灰烬、随机目标、复杂条件表达式、复制效果、角色技能、多个符文叠加。可以设计，但必须标记“需扩展核心”，先评估范围；不要把它们伪装成现有内容字段。

# Godot v1.5：精致对战场景美术需求清单

更新日期：2026-10-07。程序基线：`1.5.0-dev`；规则/卡池：`1.0.0`；正式卡池30种。

本轮目标：在现有Godot 2.5D原型上，制作一个具备精致空间、材质和对战反馈的完整主题场景。用户提出《游戏王：大师决斗》作为观感参考；本文保留完整场景的需求规格。2026-10-07已完成首批非建模资源并接入部分表现，逐项制作/接入状态见[需求核对与交付](art-resource-status-v1.5.md)；模型与完整场景验收仍未完成。

## 1. 项目状态确认

| 项目 | 当前状态 | 美术规划影响 |
|---|---|---|
| 前端与规则 | Godot本地客户端已实现；C++规则、AI和内容经GDExtension桥接，独立于前端 | 本轮修改展示资源，不重新设计玩法或权威规则 |
| 对局空间 | 固定斜俯视、3D牌桌、双方五区、牌库、三维卡牌；前景二维扇形手牌 | 已有2.5D基础，无须从零搭建3D系统 |
| 牌桌 | `table_3d.tscn`以BoxMesh/PlaneMesh组成桌体、金边和桌面；主要使用纯色材质 | 目前属于结构原型，需要定制轮廓、UV、表面细节与材质 |
| 卡牌 | 一个通用薄片模型；正反面贴图，卡边；卡面合成纹理缓存；卡面当前采用无光照材质 | 保留现有30张插画；改善通用卡体、接触感和反馈，不为每张卡建模 |
| 场地与HUD | 3D区域与卡牌；左侧只读详情、右侧连锁/可收起日志、下方手牌和操作层；详情与执行操作分开 | 使用当前全画面叠加布局，历史“右侧详情”“1600×1000固定画布”不作为当前依据 |
| 演出 | 已有移动、抽牌、翻面、解析/释放/响应/反制提示与资源飘字；消费提交结果中的cues/sounds | 新美术接已有表现接口；动画不提交规则 |
| 渲染配置 | 工程锁定Godot 4.7.2，当前Compatibility；支持1280×720、1600×1000、1920×1080检查 | 正式效果先在当前渲染器验证，不先假设所有高阶效果可用 |
| 验收 | 2.5D报告记录Release 210/210与相关Debug 5/5通过，已有GPU截图 | 原生DPI、真人连续输入、整局1080p/60fps仍待确认；自动测试不代表美术完成 |

依据为当前代码、场景、工具链锁与[2.5D交付报告](reports/v1.5-25d-client.md)。本文未重新运行该报告中的测试。

## 2. 是否需要建模

**建议需要，但以场景建模为主；精致化必须同时包含材质、灯光、构图、UI与动效。**

| 想获得的效果 | 是否需要新模型 | 合适的实现资源 |
|---|---|---|
| 桌面纹样、皮革、羊皮纸、旧金、磨损细节 | 通常不需要复杂建模 | UV、基础色/法线/粗糙度/金属度贴图；细纹和浅浮雕烘焙到贴图 |
| 厚实桌沿、倒角、雕花边框、立体书脊/包角 | 建议建模 | 改变轮廓及可见阴影的低中面数结构，重复装饰模块化 |
| 周边遗迹、石柱、台阶、烛台等空间感 | 建议建模 | 少量环境模块，固定视角下布置，主战区保持平整 |
| 卡牌翻转、悬浮、落位、牌库厚度 | 简单通用模型足够 | 圆角薄片、正反面贴图、牌堆代理模型与关键帧/Tween |
| 火球、银光反制、解析完成、目标线 | 多数无需传统高精模型 | 简单网格、特效纹理、粒子、材质动画、短镜头反馈 |
| 详情、费用、连锁信息、操作按钮 | 不需要模型 | 清晰二维Control界面、可切片框体、图标与转场 |
| 实体召唤物、角色全身演出或可互动伙伴 | 需要模型及动画，但当前非必需 | 后续单独立项，不能仅因参考游戏存在就纳入本轮 |

推荐采用“一个完整场地主题＋共用卡牌模型＋二维清晰HUD＋少量重点特效”。无需先为30张卡制作30个模型，也无需先做大型可漫游场景。

对当前GPU截图的判断：桌沿有体积但轮廓简单；桌面/区域多为同色平面，环境背景较空；区域框体像放大的二维表单，空间关系与材质缺少区分。优先改善这些主画面因素，而非先制作大量小摆件。

## 3. 视觉目标与制作边界

- 延续当前A古籍金饰方向：暗木/古籍、酒红皮革或羊皮纸、克制古金、青绿魔法。把牌桌组织为“奥术仪式空间”；这是一套候选主题，不要求本轮立刻变成写实废墟竞技场。
- 借鉴参考的空间纵深、卡牌实体感、清晰前景手牌、分层HUD、响应节奏与短促结算反馈。游戏区域仍使用巫师牌的解析/施法/言灵/行动/灰烬，不替换为参考游戏的槽位规则。
- 场景可细腻，现有卡图和像素图标继续使用；精绘框体、3D材质与像素插画的混合需要一张最终视角样稿统一观感。
- 玩牌区域最简洁；周边装饰承担氛围；文字与高亮优先可读。亮点集中在操作源、目标和结算事件，环境不持续抢注意力。
- 参考用于观感和层次评估；正式图案、主题和资产采用项目自己的设计。

## 4. 第一批：完成一个可实机评审的主题场景

P0为本轮核心交付，P1为精修，P2为后续扩展。数量按资产类型计算，共享模型和材质可实例化，不按双方重复计数。

| 编号 | 优先级 | 需求资源 | 建议最小数量 | 交付要求 |
|---|---|---|---|---|
| VIS-01 | P0 | 最终镜头场景概念稿 | 1套：空场/复杂场面2张 | 以1920×1080固定斜俯视绘制，含真实卡牌尺寸与HUD净空；再检查720p和16:10 |
| VIS-02 | P0 | 场地结构设计 | 顶视布局1张、拆件图1张 | 标注战区、边缘、环境、灯光、区域与牌库；标出装饰不得进入的选取空间 |
| MOD-01 | P0 | 主牌桌/仪式平台模型 | 1套 | 桌体、平整战区、边沿/包角拆分；具备倒角与厚度；UV和材质槽完整；保留现有区域可调整能力 |
| MOD-02 | P0 | 周边环境模块 | 3–5个可复用模块 | 基座/台阶、柱或书架、破损或装饰边块等择一主题组合；用于填补黑色空白和形成前中后景 |
| MOD-03 | P0 | 通用卡牌模型精修 | 1个 | 薄片厚度、细倒角、正反面及边缘分材质；与现有1:1.5牌体与命中边界对齐或同步更新 |
| MOD-04 | P0 | 牌库堆叠代理模型 | 1个 | 可调高度/数量标签；远处不逐张绘制全部卡牌，使用共享卡背；与灰烬区区分 |
| MAT-01 | P0 | 主场景材质 | 4套：主体、桌面、古金、环境 | 建议分别用暗木/石、皮革/羊皮纸、金属、环境石材；实际由概念稿确定，避免全部同色 |
| MAT-02 | P0 | 区域纹样与材质 | 5类区域纹样＋阵法空槽/宿主关联2类 | 采用低对比描线、刻纹或叠加网格表达；区域名动态显示，不把文字烘焙到地面 |
| MAT-03 | P0 | 卡牌正反面与边缘材质 | 1套材质配置，复用现有卡图/卡背 | 卡面清晰，纸边和背面有实体感；是否让牌面受光必须用真实小卡尺寸对比验证 |
| LGT-01 | P0 | 灯光、环境与镜头配置 | 1套Godot场景配置 | 主光/环境色/阴影/有限补光；暖场景与冷魔法分层；卡牌可见接触感；交付实际引擎视角 |
| UI-01 | P0 | 对局HUD精修 | 1套 | 阶段、双方资源、左详情、右连锁/日志、前景手牌、独立操作/确认；同一视觉语言，背景不侵入阅读区 |
| UI-02 | P0 | 卡牌交互视觉 | 5种状态及关联示例 | 悬停、选中、合法候选、已选目标、额外成本；宿主/符文关联可读，不仅改变边框颜色 |

主模型MOD-01是一套拆分场景，不等于一个合并网格；环境3–5个模块也不是3–5套完整场地。先锁定轮廓与构图再制作材质，避免先精修镜头看不到的部分。

## 5. 第二批：对战表现与环境精修

| 编号 | 优先级 | 需求资源 | 建议最小范围 | 验收重点 |
|---|---|---|---|---|
| PRP-01 | P1 | 氛围摆件模型 | 3种：灯具/书卷/晶体等 | 可复用，放在外围；不遮住牌库、手牌或目标，不增加角色玩法暗示 |
| VFX-01 | P1 | 氛围特效 | 2类：低密度尘点、外围符纹微光 | 可关闭/减弱，不遮文字，不在整个画面铺密集透明粒子 |
| VFX-02 | P1 | 解析特效 | 开始/进行/完成3态 | 对应同一视觉家族；完成不等于成功释放；各卡多次同时解析也可读 |
| VFX-03 | P1 | 准备、释放与反制 | 准备1类、通用释放1类、反制1类 | 明确区分支付宣告、响应和实际结算；反制后不会残留成功释放演出 |
| VFX-04 | P1 | 效果特效 | 伤害、治疗、魔素、荷载4类 | 图形和方向可区分；飘字不遮挡手牌和确认；数值来自展示事件 |
| VFX-05 | P1 | 关联与离场反馈 | 符文附着、阵法销毁、普通离场3类 | 阵法销毁的关联清理不重复炸屏；隐私遮挡清空未播队列 |
| ANI-01 | P1 | 卡牌动作规范 | 抽牌、落位、翻面、抬起、回位5类 | 时间、曲线、锚点、层级统一；拖放不提前支付，命中与画面一致 |
| ANI-02 | P1 | 开局/终局与镜头反馈 | 开局1段、胜/负/平局3态、轻反馈1类 | 默认固定镜头；重大事件短反馈；提供精简模式，不强制长片头 |
| UI-03 | P1 | 连锁与响应演出 | 链节进入、优先权、逆序结算、取消4态 | 信息层覆盖特效，当前来源/目标可查；忙碌场面仍知道轮到谁操作 |

首批实机效果样板建议覆盖：火球术伤害、生命缝合治疗、银光锐语反制、奥术圆环附着。复用当前卡图与真实规则，不扩展召唤物模型。随后通用组件覆盖其余卡牌。

## 6. 暂缓需求

P2：第二套及更多场地皮肤、可互动伙伴、角色全身模型/骨骼动画、每张卡独立召唤动画、360度镜头、长过场、动态场地破坏、大规模天气。当前场景精致化不以这些资源为前提。

声音沿用已有[声音需求与制作记录](audio-resource-requirements.md)及当前运行资源，按新增演出补映射；不重新把历史缺失音效当作现状。新增演出所需声音再单列。

## 7. 建模、贴图与引擎交付规范

| 类别 | 交付规范 |
|---|---|
| 模型源与导出 | 可编辑源文件（如`.blend`）＋`.glb`；部件有稳定名称；变换、法线、材质槽正确；不要求运行时安装建模工具 |
| 尺寸与坐标 | 以现有桌体19×14、卡体1×1.5的Godot单位为首轮对照，附尺寸图；Godot Y向上；战区顶面与牌体锚点统一，不能通过随意放缩破坏选取 |
| 几何层次 | 改变轮廓/阴影的结构建模，细刻纹/小裂纹烘焙；战区平面保持稳定，装饰与交互表面拆开；首轮不强制骨骼和物理碰撞 |
| 纹理 | 基础色、法线、粗糙度、金属度按材质需要交付；AO/发光/遮罩可选；标注通道、色彩空间、法线方向及UV对应；打包纹理附通道表 |
| 纹理分辨率 | 主场景建议2K图集起步，小摆件512–1K；以真实镜头调整，不默认全4K；可复用边框用条带贴图/图集减少材质数量 |
| 场景文件 | 导入模型外另交付可编辑Godot装配场景、材质与灯光配置；不把灯光和HUD不可编辑地合并进导出模型 |
| 特效 | 交付纹理/简单网格、引擎场景、持续时间、锚点、循环/结束规则、低效果版本；透明层叠和遮挡在实际相机下验证 |
| HUD | 源稿＋独立可切片PNG/图标＋边距与字号说明；文字独立渲染；现有卡图nearest，细腻框体/背景按当前规范过滤 |
| 来源与清单 | ID、版本、文件路径、用途、作者/来源、许可、导出设置、依赖、缩略图；模型、贴图、引擎场景分别追踪 |

首轮几何建议预算：牌桌/平台约1–3万三角面，单摆件约500–3000，通用卡牌约12–100；仅作起点，不作为性能承诺。真正验收同时检查可见面、绘制调用、材质切换、阴影灯数量、透明特效及纹理占用。

Godot官方推荐glTF作为3D交换格式。当前Compatibility具有功能与光照成本边界：不以Forward+专属体积雾、屏幕空间反射、Decal节点等作为首批必要条件；区域符纹可用独立薄网格/贴图实现。若高品质方案确实需要Forward+，先做同场景画质/设备/性能对比，再决定是否迁移，不能只为“更精致”先改渲染器。[模型导入格式](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/available_formats.html)、[渲染器功能对比](https://docs.godotengine.org/en/stable/tutorials/rendering/renderers.html)。

项目锁定4.7.2；技能参考资料较旧（4.6），具体效果以锁定版本的实机验证为准。

建议新增工作目录：`assets/art/3d/battlefield/<theme>/`存源与导出，Godot资源采用对应`godot/art/3d/`目录并记录映射。这是目录建议，不改变当前资产加载路径；原稿和现有30张插画不覆盖。

## 8. 制作顺序与完成标准

1. **确定一张最终视角样稿。** 同时带复杂卡牌、左详情、右连锁和底部手牌；先确认主战区大小、环境占比和主题，不以纯环境渲染图定稿。
2. **用灰模调整空间和轮廓。** 复用真实场景与命中逻辑；桌沿、环境、牌库代理先通过布局检查。
3. **完成模型材质与灯光样板。** 先精修一个角落＋一片桌面，再完成整个主题；至少完成空场/复杂场面两种实机画面。
4. **精修HUD和状态。** 卡牌小尺寸与完整规则分开，详情只读、操作独立；区域浏览保持拥挤场面可用。
5. **接入关键演出。** 先4张示例卡，再全卡池复用；暂停、换手、精简模式和重开不残留效果。
6. **真人与性能验收。** 检查720p/1080p/16:10、真实DPI、连续拖放、长期对局、低效果模式；1080p/60fps仍是待实测目标，不能用一张静态截图证明。

最终交付为一个完整可运行主题场景，包含模型、材质、镜头灯光、可读HUD和关键反馈；不是仅交付一套模型。允许灰模、精修模型、特效分批进入运行版本，各批单独记录设计/制作/接入/验收状态。

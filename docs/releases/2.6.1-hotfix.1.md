# Alpha v2.6.1 Windows 联机修复包

发布日期：2026-11-04。便携包版本 `2.6.1-hotfix.1`，程序版本 `2.6.1`；规则与卡池 `2.6.0`、机制修订 `10`，用户数据目录与 Alpha v2.6.1 一致。

进入中央服务器对局后，后台可用动作查询和初始阵法选择会同时等待服务器回复。旧客户端只保存最后一条查询，两类查询互相覆盖并不断重发，约两秒发出 76～80 条查询，触发服务器每秒 20 条、突发 40 条的限流；重连后重复，导致无法操作。

修复后，同一对局状态下分别保存各查询的等待状态和结果，重复轮询不再重发；状态、会话恢复、房间暂停状态或查询代次变化时失效旧结果，另一名玩家重连恢复后也会重新查询。缓存上限 128 条。服务器限流保护保留。另修复服务器消息处理失败关闭 TLS 后，接收循环继续访问空对象的问题。

修复选择初始阵法时的另一处断线：Godot JSON 解析器将整数转成浮点数，导致原生层拒绝完整动作中的命令类型、卡牌编号等整数。TLS 传输现将原始 JSON 文本交给原生解析器，保留整数类型与精度，继续执行原有严格校验。

中央服务器程序同步到 `2.6.1`，与 Windows 客户端一致，解决旧服务端 `2.6.0-hotfix.1` 生成的终局复盘被新客户端拒绝的问题。

请完整解压 `WizardCard-2.6.1-hotfix.1-windows-x64.zip`，运行其中的 `WizardCard.exe`。不要只替换 EXE；修复同时包含于 `WizardCard.pck` 和 `bin/wizard_godot_bridge.release.dll`。

验证过程与部署记录见[交付报告](../reports/2.6.1-hotfix.1.md)。

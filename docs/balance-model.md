# 巫师牌数值数学模型 v0.2

依据：Alpha v2.5.0 时的45种卡快照、当时规则/卡池版本和 `mechanicsRevision`，以及规则引擎实际支付和结算行为。当前正式卡池已扩展为62种卡；本文参数与逐卡测算未覆盖后续卡牌，应作为历史基线，不用于当前卡池的平衡结论。模型仍是静态估算，不是胜率结论。正式卡牌以 `assets/catalog.json` 与清单列出的单卡定义为准，`assets/cards.json` 是兼容聚合产物。

首先采用设计约束：**无强条件的一费抽二明显超模。** rc.2 将奥术回想调整为2费抽2，并保留1点临时荷载；该数值是第一轮待测基线，不代表已由胜率模拟证明平衡。免费高产费阵法、抽牌与爆发魔素互相加强，先校准资源系统，再校准伤害和干扰。

逐卡数值及候选见[测算报告](reports/card-balance.md)，可机器读取的指标见[JSON](reports/card-balance.json)，先验参数见[参数文件](balance-parameters.json)。生成器为 [`tools/analyze_balance.py`](../tools/analyze_balance.py)。

## 1. 实际规则基线

| 资源/规则 | 当前实现 | 对模型的影响 |
|---|---|---|
| 生命 | 初始/上限40 | 评价伤害要看致死距离；治疗会溢出 |
| 魔素 | 初始1，上限12，可储存；自己的准备阶段基础收入1 | 费用没有每回合重置，魔素价值随收入和库存改变 |
| 初始阵法 | 小六芒星：容量5、收入1；其他阵法不具备初始资格 | 加上玩家自带容量2，开局容量7、每轮基础收入2；其他阵法通过副卡组配方设置或替换 |
| 手牌/牌库 | 起手5，结束阶段上限8；主卡组40，同名最多3 | 出牌的卡牌消耗必须计价；抽牌失败败北 |
| 先后手 | 先手首次不自然抽牌；双方首次正常收入 | 第一主要阶段魔素通常为小六芒星3 |
| 行动 | 无每回合次数上限 | 抽牌、产费、强制荷载可在一回合连用 |
| 阵法 | 总阵体5，每个自己的回合一次阵法操作 | 不能把产费展开当作一次完成；初始阵法开局免费入场，是否受保护取决于卡牌效果 |
| 解析 | 默认等待下个自己的准备阶段；解析/施法分别支付 | 必须同时记等待、费用曲线、环位、峰值绑定荷载 |
| 言灵 | 预置支付并绑定荷载；3个后场位；禁止手牌响应 | 反制有提前承诺成本，不能按随时可打出计算 |
| 符文 | 一个宿主最多一个；按 `cost` 付费，附着本身不增荷载 | 产费符文只有手牌、费用和宿主机会成本 |
| 荷载 | 绑定、普通临时、来源临时、独立；严格超过容量败北 | 是硬约束，临界附近不能按线性扣分 |
| 专注 | 最多一个；准备阶段先维持再收入；追加绑定荷载 | 收入不能补付本次维持，维持负担逐次累积 |
| 持续 | 持续3含首次释放回合；后续触发只在后续阶段 | 紊乱波动应算5→8→11，而非5+3×3 |

来源优先级采用**代码与实际数据 → 最新规则规范 → 旧设计稿**。当前[设计指南](card-design-guide.md)有三处需要在后续规则文档维护时统一：阵法章节写“按阵体设置”与代码按 `cost` 支付冲突；符文章节写“形成绑定荷载”与 `AttachSeal` 实现冲突；同页字段表又使用 `cost`，互相不一致。模型按代码取值，没有修改规则来迎合文档。

核对位置：`Rules::capacity/analysisCost/castCost/load`、`EffectResolver::apply` 位于 [state.cpp](../src/core/state.cpp)；设置、支付、离场、专注和阶段触发位于 [engine.cpp](../src/core/engine.cpp)；字段默认解析时间1见 [content.cpp](../src/content/content.cpp)。[最新卡牌规则](alpha-v1-cards.md)与上述阵法费用和容量一致。

## 2. 模型分为状态、资源、效果三层

### 2.1 状态与真实目标

记录状态

```text
s = (双方生命/临时生命，魔素，手牌/牌库，阶段/优先权，
     场上卡与解析进度，阵体/环位/后场占用，
     绑定/临时/来源/独立荷载及期限，待结算链节)
```

真实价值应为 `V(s)=在该状态下、给定双方策略时的获胜概率`，卡牌价值为 `ΔV=V(执行后)-V(最佳替代行动后)`。完全信息的极小极大求解可作为理论参照；实际有隐藏手牌和牌库，必须对玩家已知信息下的可能状态取期望。这里没有求解这一完整博弈，也没有用现有AI启发式分数充当胜率。

先用资源向量筛查：

```text
X(card,s) = (实际魔素支出，净手牌变化，等待自己的回合数，
             宣告时绑定荷载，释放后残留荷载，各类荷载占用时间，
             阵体/环位/后场占用，实际伤害/治疗/防护，
             后续可用收入，取消/销毁/检索/加速等条件效果)
```

同一用途的卡才直接比较。当A在同一可执行状态下费用更低、收益更高、等待不更长，且没有额外约束，就存在需要解释的优势。伤害类型、位阶、目标及响应时点不同，须拆情景再比较，不能宣布所有状态下严格支配。

### 2.2 通用的局部估值式

在远离终局、资源变化较小的状态下，可用局部近似：

```text
R(s) = λH(s)·Δ有效手牌 + λD(s)·实际伤害
     + λHP(s)·有效治疗/防护 + 折现后的可用收入
     + 条件/时机价值 - 实际魔素支出
     - 荷载占用成本 - 场地机会成本 - 暴露/失效风险
```

单位统一为“该情景下的魔素等价”。`λ` 是资源的边际价值，而非自然常数：低手牌时多一张牌更贵；高收入/魔素溢出时支付1魔素更便宜；临近致死时1伤害可能直接决定胜负。抽牌模型中的 `λH` 不直接套到伤害牌上给统一总分；当前缺少拟合 `λD/λHP` 的对局数据。

一张留在场上的阵法不能既扣“消耗1手牌”，又把其持久功能漏算；一张法术不能既把解析+施法费都列支，又再把等量荷载误当第二次付魔素。费用是花掉的流量，荷载是持续占用的容量。

## 3. 抽牌定价：一费抽二为什么超模

### 3.1 净赚牌数与实际可保留牌数

无额外弃牌时，抽 `n` 张的净手牌变化为 `n-1`，减1是打出抽牌卡本身。设行动前手牌数H，后续打出u张，最终额外弃牌d张：

```text
H_end = H - 1 + n - u - d
溢出弃牌 o = max(0, H - 1 + n - u - d - 8)
净保留牌数 = n - 1 - d - o
```

例：H=5，抽二后6张，净赚1；H=8且后续不出牌，抽二后9张，结束弃1，净保留0。但超限不立即弃牌，中间仍能出牌、选择更好的8张，不能把这一情景判作完全无收益。牌库少于抽牌要求会抽牌失败败北，不能把“至少抽到一张”计作收益。

### 3.2 将用户提示作为设计先验

对安全、无溢出损耗、牌库充足的奥术回想：

```text
R_draw = (n-1)·λH - c - l·λT
c_balanced ≈ (n-1)·λH - l·λT
```

`l` 为本回合临时荷载，`λT` 为其在安全状态的局部机会成本。使用卡牌价格 `λH=2～3`、中央值2.5；本回合临时荷载 `λT=0～0.3`、中央值0.15。**这些是与“一费抽二超模”相容的设计假设，不是从胜率测得的系数；用户提示只能约束方向，不能唯一识别价格。**

| 抽二费用 | 净手牌 | 中央净收益 | 先验范围 | 解释 |
|---:|---:|---:|---:|---|
| 1 | +1 | +1.35 | +0.70～+2.00 | 在全部安全情景先验中明显赚资源 |
| 2 | +1 | +0.35 | -0.30～+1.00 | 第一轮候选；高收入环境仍可能过强 |
| 3 | +1 | -0.65 | -1.30～0.00 | 上界对照；低收入前期可能太慢 |

当前1点临时负担在自己的结束阶段清除；正常对手主要阶段到来前就消失。它主要限制本回合出牌，而不是给对手下一回合的魔力扰动增加稳定机会。不能将其定价为永久荷载。

**建议：先测试2费抽2、保留1点本回合临时荷载。** 若资源展开后仍成为无条件满编，再比较3费版。若坚持1费，应减少净赚牌：1费抽1，或抽2再弃1；后者仍有筛选质量收益，且额外弃牌目前需要检查具体实现方式。每回合一次、按剩余手牌数限制等属于新增规则，当前JSON不能仅凭文字表达。

### 3.3 卡池中的组合放大

| 组合 | 魔素净变化 | 手牌净变化 | 主要约束 |
|---|---:|---:|---|
| 回想 | -1 | +1 | 1点本回合临时荷载 |
| 回想→复苏 | +2 | 0 | 合计3点本回合临时荷载；抽到/已有复苏且魔素不溢出 |
| 克敌机先→回想 | -2 | +1 | 检索增加1费；言灵1绑定释放后清除，回想再留1临时 |
| 克敌机先→复苏 | +2 | -1 | 检索1费；复苏2点本回合临时荷载 |

净手牌以整个组合的开始/结束计；回想与复苏共消耗2张、抽回2张，因此不能重复给回想的+1和复苏的产费而漏掉复苏消耗。三个同名上限和有限牌库使循环有上限，但不限行动次数允许一回合爆发。

30张牌中放3张回想，起手5张看到至少一张的概率：

```text
P = 1 - C(27,5)/C(30,5) ≈ 43.35%
```

再放3张克敌机先，起手看到回想或检索入口的概率约70.17%。它表示有入口，不保证费用、目标、荷载和后续牌序可用。报告覆盖 `assets/presets.json` 的8套牌表，以及 `assets/deck.json` 的默认示例牌表，共9套，与客户端 `loadPresets` 一致。

## 4. 魔素经济：把费用放到每轮收入里

### 4.1 收入、库存与费用压力

```text
I_t = max(0, 1 + Σ场上阵法收入 + Σ阵法符文收入修正)
准备收入前先支付专注维持
M_after_income = min(12, M_before_income + I_t)
费用压力 = 卡牌实际总费用 / 本轮收入
```

费用压力只是节奏诊断；由于库存可保留，还必须检查每次宣告的实际库存。小六芒星基础收入2，奥术回想2费占100%；小六芒星加一个逆三角星符收入4，占50%；小六芒星加两个恩格亚斯四角星收入8，占25%。低费抽牌会在产费结构展开后愈发廉价。

### 4.2 产费卡的折现与回本

设未来还有T次自己的准备阶段，折现 `δ`、存活概率 `p_t`、新增收入实际利用比例 `u_t`：

```text
PV_income = Σ(t=1..T) δ^t · p_t · u_t · ΔI_t
R_engine = PV_income - 设置费 - λH - 场地/宿主机会成本
```

新设置阵法与符文不会追补本回合已过去的收入。取T=3、δ=0.85、p=u=1、λH=2.5，仅作满利用筛查：

| 扩展卡/阵法附着 | 设置费 | 每轮新增收入 | 3次收入折现合计 | 扣费及卡牌价格后 |
|---|---:|---:|---:|---:|
| 均衡之六芒星（扩展） | 0 | 1 | 2.19 | -0.31 |
| 五芒星 | 1 | 2 | 4.37 | +0.87 |
| 四角星 | 0 | 3 | 6.56 | +5.56 |
| 逆三角星符 | 2 | 2 | 4.37 | -0.13 |

此表**只算收入**：均衡之六芒星作为扩展阵法提供10容量、3环位；四角星提供较少容量但有免费加速；符文要占唯一附着位。不能据此把均衡判弱。逆三角星符可以附着于受保护的扩展或初始阵法；免费四角星的“2容量”是少量正收益，不能误当其自身带来2点负担。

合法展开示例：小六芒星初始占1阵体，连续两个自己的回合各设置一张恩格亚斯四角星，第三个自己的回合收入达到8、容量11、总阵体3；再用下一次阵法操作设置阿克乌姆之弧，总阵体4、容量26，收入仍为8。若改为三张四角星，则总阵体4、容量13，下一次准备总收入11。需要多回合和多张手牌，不能视作开局自带。

rc.2 已将恩格亚斯四角星收入由4调至3、逆三角星符费用由1调至2。后续应分别比较四角星收入3/4与逆三角星符费用1/2，并记录阿克乌姆之弧提供容量后是否成为必带。生命之五芒星和均衡之六芒星均为扩展阵法，不能作为初始阵法；其配方成本和独立荷载应按当前卡池计算。

### 4.3 手牌与魔素是两个相互影响的瓶颈

设一轮自然抽牌b张，使用抽牌卡a张，每张抽n张，其余打出非抽牌卡x张、额外弃牌q张，则手牌库存守恒为：

```text
H_next - H = b + a·(n-1) - x - q
在手牌库存不持续下降的有限观察期内：x ≤ b + a·(n-1) - q
魔素需求 ≈ a·抽牌费用 + x·平均非抽牌支出
```

通常b=1；没有额外抽牌时，长期平均只能补充每轮1张新牌，高收入会遇到缺牌而闲置。有回想时，抽牌净赚手牌、使额外产费更能被利用；更多产费又让抽牌费用更轻。这是两类卡互相放大的原因。

仅作算例，若有限观察期内平均每轮用一张回想，非抽牌平均支出2.5，则可支持每轮2张非抽牌卡，魔素需求约 `1+2×2.5=6`；回想改2费时需求变7。这个2.5是算例设值，不是全卡池平均或实测。回想最多3张、牌库有限，不能据此宣称无限稳态。对局数据应计算“有多少收入因为缺牌/时机/荷载而未用”，再拟合实际利用率u。

## 5. 荷载：必须用过载阈值模型

```text
L = L_bound + L_temporary + L_source + L_independent
K = 2 + Σ阵法容量 + Σ容量修正
S = K - L                      # 剩余容量
主动宣告必须满足 L + 新增宣告负担 ≤ K
状态检查时 L > K 则败北
```

声明为 `burden` 的负担在宣告时验证；回想和复苏当前使用的是主效果里的 `temporary`，负担在效果结算时生成。不能把“能够宣告”误当作“结算后安全”：剩余容量不足时，它们仍可能导致自身败北，且不能在同一链节两句之间使用解压牌。

### 5.1 安全区域的占用与临界区域的胜负

安全区域可估计 `成本≈Σ λK(t)·荷载占用量·占用时长`。`λK` 随S减小而上升；阵体槽满且无法扩容时更高。在临界区域直接判断合法性和胜负，不能继续用固定“1荷载=0.2费”。

魔力扰动给对手4临时荷载：

```text
直接过载条件：S_opponent < 4
P(直接过载) = P(S_opponent ∈ {0,1,2,3})
```

这一概率应从“本卡有合法使用机会时”的对手状态分布估计。对手可能放弃法术释放荷载、或通过已设置响应干预，因此不能从任何随机回合的负载平均数直接推导实际胜率。

例：均衡K=10、L=7，单张扰动后L=11败北；L=6则L=10安全。两张连续扰动合计8，需4魔素、2手牌；无介入时对手L≥3就超过10。第一张后存在合法响应时要逐链处理，不能把两张当作不可响应的一项效果。

来源关联的紊乱波动：施法者通常先容纳8绑定荷载（五芒星减费后7），对手分别承受5、8、11来源荷载；K=10且原L=0的对手，若无人清除、来源持续存活，会在第三次自己的施法阶段触发后败北。清临时荷载和销毁来源会改变序列，持续结束离场统一移除残留来源荷载。

### 5.2 清除不等于事后救命

心如止水1费且另弃1手牌；次级复原3费，解析立即完成、清临时并至多治疗2。清除都不清绑定/独立荷载。若已经在状态检查过载败北，无法等下一回合再救。

次级复原还有先支付、后清除的问题：需要先容纳3绑定荷载。例如K=10、L=8时，不能先宣告这张牌再声称其会清临时；心如止水自身不新增绑定荷载，可在合法自己的主要阶段清除。但两者均是1速通常操作，不能从手牌突然响应对手扰动。

### 5.3 独立荷载是不可忽略的永久预算

当前30张卡中没有 `clear_independent` 效果。生命缝合、虚假生命留下的2独立荷载不会自行到期，也不会随自身离场清除。

设原独立荷载为J，其他残留荷载B，释放前绑定费用C，释放后再留下2独立：每次使用要分别满足 `J+B+C≤K` 和 `J+B+2≤K`。不能只用 `floor(K/2)` 判断可重复多少次。

例：均衡K=10、其他B=0，虚假生命C=3。四次施放后J=8，虽然8≤10，但第五次先需要8+3=11，不能宣告。实际主卡组同名最多3张；若同时放两类牌，二者共同消耗这份永久预算。

## 6. 伤害、治疗和持续效果

### 6.1 伤害曲线按分段费用与时点比较

| 卡 | 解析/施法 | 总费 | 五芒星总费 | 伤害 | 通常伤害/总费 | 核心区别 |
|---|---:|---:|---:|---:|---:|---|
| 火花术 | 设置1 | 1 | 1 | 2火 | 2.00 | 立即释放、无阵法要求 |
| 寒霜射线 | 1/1 | 2 | 1 | 3寒 | 1.50 | 一阶、启动低、默认等一轮 |
| 火球术 | 3/1 | 4 | 3 | 10火 | 2.50 | 二阶、压缩伤害、默认等一轮 |
| 闪电束 | 3/2 | 5 | 4 | 8电 | 1.60 | 二阶、同解析等待、非火伤 |
| 魔法飞弹 | 2/2 | 4 | 3 | 3力 | 0.75 | 可快速响应、可拆埋伏 |

伤害/费用未扣1张牌消耗，也未给时机与负担定价，只适合筛查。在40生命、无防护减免下，火球需4次，闪电需5次，寒霜需14次，火花需20次；同名上限3意味着实际要混合威胁，不能将理论次数当作一副牌必然可完成的击杀路线。

火球与闪电同为二阶、默认等一轮，火球少1费、多2伤、峰值绑定也低1；额外销毁自己的空阵法可跳过，不是必须负担。非火环境中差距缺乏补偿。火抗将火球10减到5，但闪电仍8，环境价值真实存在。建议先固定一张为参照，再测试闪电伤害8→10，或解析费3→2，分别测而非同时增强。若后续定位火球本身过强，可反向削减火球；当前缺少数据决定哪一端最合适。

### 6.2 防护与治疗的有效量

```text
有效治疗 = min(治疗量, 40 - 当前生命)
新增临时生命 = max(0, 本卡数值 - 当前临时生命)
实际防护价值 = 预期在结束前被消耗的临时生命
```

临时生命无回合到期，但取较高值、不叠加。支援术2费5临时生命、护盾术2费6且可响应；支援有立即解析，护盾要提前设置且占后场/绑定荷载，需按使用时点比较。虚假生命3费8临时生命并留2独立荷载：已持有6点时只增2，永久负担仍为2。

避火咒的防护价值应逐次计算：火伤d在抗性下剩 `floor(d/2)`，防护 `ceil(d/2)`。它首次2费，此后每次维持另付2魔素并累积2荷载，最多一个专注；不是一次2费永久免半伤。面对多次10火伤，每次可减5；只面对闪电、寒霜时收益0。

### 6.3 炽燃结界的专注曲线

维持k次，普通基础且不附符文：

```text
累计魔素 = 2 + 1 + k
绑定荷载 = 3 + k
累计伤害 = 2 + k
小六芒星初始阵法上的费用/荷载 = 2 + k；扩展阵法的配方和承载能力另按卡牌定义计算，伤害不变
```

首次3费2伤，维持3次后6费5伤、绑定6荷载。边际每次1费+1累计荷载只换1伤，同时需要保留魔素在收入前支付。当前产费、抽牌环境能支持高伤瞬时法术，它的累计输出明显缺乏竞争力。候选是周期伤害1→2；若采用免魔素维持，则涉及专注规则及相应荷载，需单独设计实现，不能仅写卡面。

## 7. 条件效果不能用固定加分掩盖空目标

| 类别 | 正确评价方法 | 当前卡例与问题 |
|---|---|---|
| 检索 | 净手牌0 + 命中所需行动的质量提升 - 检索费 | 克敌机先1费，对回想/复苏增加稳定性；无合格候选不赚牌 |
| 加速 | 本轮提前释放相对下轮的收益 - 额外费/临时负担 | 瞬发回路过载2费，负担按实际解析支付；四角星自带免费一阶加速 |
| 取消准备 | 延迟收益 + 对手本次施法费用损失 | 银光锐语5费；对方火球仅损失施法费1、保留解析，额外准备自身仍付费 |
| 销毁法术 | 阻止效果 + 对方整张牌/已付费用损失 | 法术反制4费四速；临时负担按目标实际施法费，不是总费 |
| 销毁阵法 | 削收入/容量造成的后续收益 × 合法目标存在概率 | 碎环术2费另弃阵法牌；仅空白扩展目标，储容免销毁、基础不可拆 |
| 拆埋伏 | 目标价值 × 有有效埋伏的概率 | 飞弹拆埋伏为可选；空目标场景只得3伤 |
| 行动封锁 | 被推迟/失去的最优行动收益 - 等待与4费用 | 昏昏入睡仅禁对手下一回合行动，不锁所有施法 |

反制的峰值负担要按状态演算：预置反制已占4绑定荷载，成功发动后离场释放这4，另留下目标实际施法费等量的临时荷载。不能在结果里同时长期保留原4绑定及新增临时；埋伏反转则先另付设置费用并满足宣告容量。银光锐语和法术反制作用对象不同，但5费仅取消准备对比4费销毁，说明锐语需重点补偿；候选费用3或4，不将附带可选准备误算为免费施法。

奥术圆环在法术成功首次释放后返还实际设置费，附着本身1费、额外用1张牌。火球通常 `3+1+1-3=2` 净魔素，五芒星 `2+1+1-2=2`；两者宣告前仍分别需要总支出5/4，峰值绑定4/3，返还不能提前付款或解除荷载。附在1费火花上净支出仍1但多消耗符文，资源意义很弱。附在阵法上只有+1环位，须与该宿主附产费符文的机会成本比较。

昂扬法术模式附着1费、另加施法1费，共额外2魔素和1张牌换2力场伤害，增加1绑定荷载；其价值偏向伤害类型、组合与一次效果压缩。阵法模式容量+1、位阶+1但每轮收入-1，不能把两种模式的好处叠在同一实例上。

## 8. 第一轮实验安排与需要收集的数据

先做资源实验，再做伤害、专注及反制补偿；每组只改变一项关键参数，保留基线牌表和版本以便复盘。

| 顺序 | 实验 | 要验证的问题 |
|---|---|---|
| 1 | 回想费用2/3两组，以rc.2的2费为基线 | 2费是否仍无条件满编；3费是否拖慢缺牌恢复 |
| 2 | 四角星收入3/4；逆三角星符费用2/1，分别测试 | 魔素是否过快失去稀缺性；加速/产费是否压过其他选项 |
| 3 | 回想×复苏×克敌机先的组合与去掉单项的牌组 | 强度来自抽牌本体、产费本体，还是组合一致性 |
| 4 | 固定经济后，闪电伤害8/10或解析费3/2；结界周期伤害1/2；锐语费5/4/3 | 弱牌是否获得独立用途，是否引入新的过强组合 |
| 5 | 保持扰动4，对容量/防护与来源荷载做压力情景 | 荷载策略是否只能二选一为无效或立即致死 |

应同时记录：先后手、基础阵法、牌表/随机种子；自己的回合数；首次产费展开回合；每轮收入、魔素溢出、实际支出；手牌净变化与结束弃牌；荷载曲线与剩余容量；法术等待、空目标、被取消次数；生命/过载/抽空三类终局；致胜牌与组合；某张牌有机会使用时的实际选择频率。

胜率之外还要看普适性：同名3张长期被不同方向牌组同时选择、没有明显替代项，是必带风险；某张牌的原始胜率可能只是它常出现于优势局。使用次数和胜率相关不证明因果，需同牌组换卡/改数值对照。

探索性起步可用5个代表方向两两对战，共10组配对，每组两种先后手各20局，共400局/候选版本；使用配对种子，另测镜像检查先手。每配对40局的置信区间仍很宽，不能据此证明达到45%～55%。近50%时，独立样本约需385局才有约±5百分点的95%误差范围；配对种子或重复玩家/固定AI可能有相关性，应按实验批次/种子聚类，不直接套独立样本公式。现有AI对局只适合规则与明显风险筛查，真人策略分布还需验证。

## 9. 复算方式与边界

```powershell
python tools/analyze_balance.py
python tools/analyze_balance.py --check
```

脚本仅使用Python标准库，读取正式卡池和9套预设（含默认示例牌表）；生成逐卡资源表、抽牌费用敏感性、产费折现、专注/来源荷载曲线、起手入口概率和输入哈希。`--check` 只检查报告是否与当前数据/参数一致，不写文件。新增卡会获得“未人工评估”标签，避免继承不存在的平衡结论。

本模型没有给全卡统一排名、没有模拟胜率，也没有证明任一候选已经平衡。单卡费用表默认无符文、无反制、无其他既存负担；动态反制负担、加速及独立荷载需要按场景另算。规则引擎改动后必须重新核对状态假设；仅重跑脚本不足以保证语义一致。

# Alpha v2.6.1 Windows 中央服务器联机修复

日期：2026-11-04。便携包标签 `2.6.1-hotfix.1`；程序及中央服务器版本均为 `2.6.1`。规则、卡池仍为 `2.6.0`，机制修订 `10`，内容指纹 `41eac6fc263abd5e`。

## 故障与修复

通过两个 Windows Godot 客户端连接公网 `aq.rainplay.cn:23513`，使用正常房间界面创建、加入、准备并进入游戏，稳定复现反复连接和断开。

1. **并行查询互相覆盖。** 后台可用动作发现和前台初始阵法选择共用一个原生查询槽，丢弃对方的在途请求与结果，再次轮询便重新发送。原版在约两秒内发出 76～80 条查询，触发服务器每秒 20 条、突发 40 条的限制。`GuestSession` 改为按请求、会话、代次、状态版本和意图分别关联结果，当前状态最多缓存 128 条；状态或恢复上下文改变时清理。服务器限流参数保持原值。
2. **JSON 整数类型丢失。** 消除请求风暴后，实际点击初始阵法仍触发 `invalid unsigned integer`。Godot 将网络 JSON 的整数解析为浮点数，再传回 C++；完整动作的严格整数校验因此失败。改为将原始 JSON 文本送入原生桥接，由原生解析器解析，保留协议类型及精度，不放宽命令校验。
3. **关闭 TLS 后继续读取。** 原生消息处理失败会关闭传输，但接收循环仍继续使用已清空的 TLS 对象。现在在回调后检查传输阶段，关闭即停止接收和发送循环。
4. **终局复盘程序版本不一致。** 旧服务器版本为 `2.6.0-hotfix.1`，与新客户端的复盘版本检查不符。已部署服务器 `2.6.1`，双方终局复盘按原有规则验证，不放宽历史复盘兼容性。
5. **另一席位恢复后的旧查询。** 对方重连期间收到的 `room_paused` 结果可能在状态版本不变时保留，造成恢复后无法继续查询。房间重连、存储阻塞、技术暂停状态变化均清理原生查询缓存；同版本技术暂停快照也会使缓存失效。已用在途查询跨越对方断线和恢复的原生测试观察修复前失败、修复后通过。

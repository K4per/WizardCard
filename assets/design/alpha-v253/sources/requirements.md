# Alpha v2.5.3 需求清单

核对日期：2026-10-22。本文根据 `10.22` 目录中的改动报告、玩家规则书、法术/符文/阵法列表及味契、恒风系列卡牌资料整理。下列项目均待实现与验收；设计稿中的“待定”内容及本文列出的规则歧义，须先确认后才能作为正式规则发布。

## 1. 规则更新与缺陷修复

### 1.1 开局魔素与费用

- [ ] 按 10.22 玩家规则书，将双方开局魔素设为 0，并移除旧初始化流程中与此规则冲突的初始魔素/初始费用配置。
- [ ] 核实改动报告中“不再有初始费用，默认从0开始”所指字段。若指开局魔素，统一使用“开局魔素”；若指另一种成本，先明确其规则定义，不能误改卡牌设置费用或发动费用。
- [ ] 回归魔素上限 20、魔素保留至后续回合、抽卡阶段由阵法产出魔素，以及先手首个抽卡阶段跳过抽牌的规则。

### 1.2 盖伏不再受阵法等级与法术阶级限制

- [ ] 盖伏法术时不检查阵法等级是否达到法术阶级；仍须校验阵法归属、可用环位、卡牌区域及其他通用合法性条件。
- [ ] 低等级阵法上的高阶盖伏法术不能反转、准备施法或发动，只能按规则放弃送去灰烬区。合法动作、前端按钮和权威命令校验必须一致，不得只在界面隐藏按钮。
- [ ] 解析法术的表侧设置仍按阵法等级与法术阶级校验；本项只调整盖伏，不扩大到表侧设置。

验收：高阶法术可盖伏在低等级阵法上；不能反转/发动且可放弃；表侧设置仍拒绝等级不足的阵法；单机、联机和回放状态一致。

### 1.3 修复言灵法术的合法响应动作

玩家反馈：己方回合中，场上已盖伏的 2 速及以上法术可在适用时点响应，但手牌中的 2 速及以上言灵法术未能作为合法动作提供。

- [ ] 按咒文速度时点表和优先权规则，补齐手牌言灵法术的合法动作生成、权威校验及前端入口。言灵法术的设置、准备施法和发动按其规则作为一次动作处理。
- [ ] 只在该速度允许的阶段、时点和连锁条件下提供动作；不能因其为言灵法术而遗漏，也不能将所有手牌言灵法术无条件开放为响应。
- [ ] 同步检查合法动作列表与手动命令路径，避免“按钮可点但内核拒绝”或“界面不显示但命令可执行”。错误反馈应指出速度、阶段、优先权或额外条件中实际未满足的一项。

验收：在 10.22 规则允许的己方主要/施法时点，合法的手牌 2 速及以上言灵法术可用；速度不符、时点不符、无优先权或额外条件不满足时仍被拒绝；不重复支付费用或建立链节。

### 1.4 卡牌规则文本与效果调整

- [ ] 【味契·风味转化】发动时须将己方场上一张【味契】符文送去灰烬区；结算时从卡组选择一张【味契】符文，附着到己方【味契·魔力坩埚】。校验发动成本与结算目标，目标失效时按统一连锁规则处理。

- [ ] 【元素之环】调整为其上设置的塑能法术造成的伤害 +1；与其他伤害增减、伤害类型和多段伤害的应用顺序统一，并避免每段/每目标的重复触发歧义。

## 3. 新增单人调试控制台

调试控制台仅用于单人对局，不改变多人联机的权威规则或协议。命令应调用规则状态接口并产生日志，不允许直接改写前端显示值。

- [ ] 将指定卡牌从虚空加入手牌；卡牌通过 ID/卡名选择，校验数据存在并记录为调试操作。该操作不计为抽牌；手牌已达上限时拒绝执行且不修改状态。
- [ ] 增加获得/失去魔素、获得/失去生命、获得/清除荷载的命令，支持指定玩家和数量；明确生命是普通生命还是临时生命，荷载操作须可区分绑定、独立和临时荷载，不能留下错误来源引用。
- [ ] 增加无限生命、无限魔素、无限荷载上限的独立开关和状态显示。开启无限生命/魔素时，游戏规则造成的生命/魔素扣减及资源门槛均不阻断本次效果，状态栏显示“∞”；控制台的直接增减命令仍操作实际数值。开启无限荷载上限时，荷载仍正常累计并显示，但不因超过荷载上限受到过载真实伤害或判负；关闭开关后立即恢复常规规则判定。
- [ ] 增加“回到上一回合”操作，默认回到紧邻的上一回合开始状态；恢复双方完整规则状态、随机数状态和回放位置。无可用历史快照时禁用并说明原因。
- [ ] 所有控制台命令仅在本地单人对局中可用；在线房间、联机客户端、观战和回放中均不可调用，且须由权威会话模式校验，不能只靠前端隐藏入口。
- [ ] 显示命令参数、执行结果和失败原因；非法输入不得部分修改状态。调试改动须在日志/回放中可识别，并标注该局包含调试操作。

验收：逐条验证命令成功/失败、边界数值、回退后规则状态和随机序列一致；尝试从联机、观战和回放入口调用时均被拒绝；关闭无限状态后常规资源、过载和胜负判定恢复。

## 4. 多人联机支持域名解析

- [ ] 联机地址支持 DNS 域名及现有 IP 地址输入，解析成功后连接对应服务器；保留端口解析、默认端口和已有 IP 直连行为。
- [ ] 域名解析失败、超时、无可用地址或连接拒绝时，向用户显示可理解的错误并允许重试；不能卡死对局界面或误报为协议/版本不匹配。
- [ ] 检查 IPv4/IPv6 解析结果与当前传输适配的兼容性；域名解析不修改规则内核、对局命令、内容校验或回放格式。
- [ ] 覆盖有效域名、无效域名、域名多地址、端口错误、解析超时、断线重连及已有 IP 地址连接的客户端测试。
- [ ] 调查联机测试中出现的“超过4MiB”提示：记录提示来源、触发操作、对应消息/数据类型、大小统计口径及是否发生在发送或接收阶段；确认它是单纯诊断信息、传输限制还是实际错误。
- [ ] 验证超过 4 MiB 时对正常对局的具体影响，包括是否导致命令/状态同步失败、延迟、断线、重连或回放数据异常；若可影响正常玩法，定位并处理原因，必要时优化消息体或调整有依据的限制。若只是测试诊断提示且不影响对局，说明提示含义并避免将其误报为玩家错误。

验收：域名与 IP 均能按配置连接；DNS 故障可诊断且可恢复；联机双方规则结果及内容版本校验不受影响。“超过4MiB”提示的来源和实际影响有复现记录及结论，普通对局不会因此出现未处理的同步失败或无反馈卡死。

## 5. 玩家状态栏与对局复盘

- [ ] 为生命、魔素、荷载添加清晰一致的图标和文字标签，适当增大数值字号、优化层级、间距、对比度及资源状态反馈；图标不能成为唯一信息来源。
- [ ] 状态栏区分普通生命与临时生命、当前魔素与上限、当前荷载与荷载上限；临时生命按规则在己方抽卡阶段清除，荷载可查看绑定/独立/临时来源。
- [ ] 在对局复盘/回放界面显示双方状态栏，并随回放时间点正确更新双方的生命、临时生命、魔素和荷载；跳转、逐步播放和暂停后状态不得残留为当前实时对局值。
- [ ] 新增对局日志查看面板：默认隐藏，通过清晰可见的日志按钮打开，再次点击或关闭按钮可收起；打开时显示按发生顺序排列的对局事件，并在新事件到达时保持可读且不遮挡必须操作的控件。关闭面板不清除日志，也不影响回合和命令处理。
- [ ] 日志至少覆盖阶段/时点变化、设置/盖伏/反转/准备施法/发动、连锁与结算、资源变更、目标选择、卡牌离场及胜负判定；事件文本使用玩家可理解的名称和数值，避免只显示内部命令名或调试字段。
- [ ] 对局弹出 UI（包括目标选择、费用/效果选择及确认提示）中的“确认”和“放弃”按钮置于弹窗中部的明显操作区域，两个按钮均须清晰可见且易于区分；确认作为主要操作突出显示，放弃作为次要操作仍有足够对比度和可点击面积。
- [ ] 弹窗打开时限制底层对局操作，按钮不能被手牌、日志面板或其他浮层遮挡；验证鼠标与键盘焦点、窗口缩放、低分辨率和长文案下的位置、可读性及误触防护。
- [ ] 检查常用分辨率、窗口缩放、长卡名/大数值、提示框和不同屏幕布局，确保状态栏不遮挡操作区、选择目标或关键日志；颜色与图标需有足够对比度。

验收：正常对局和复盘均可同时辨认双方状态；资源变化与规则日志一致；日志默认收起且可随时查看，不阻塞对局；弹窗确认/放弃按钮位置醒目、操作明确且不误触；回放任意时点显示对应快照，缩放后无裁切、遮挡或图标错位。

## 6. 发布与回归

- [ ] 更新版本号、规则版本、卡池版本、机制修订号和内容 hash；同步维护联机内容匹配与回放兼容策略。
- [ ] 交付逐卡同步差异报告，列出每张卡的来源、稳定 ID、数据变更、效果实现状态、图像状态、待定规则及对应测试。
- [ ] 完成开局魔素、盖伏限制、言灵响应、卡牌规则修订、调试控制台隔离、DNS 连接、“超过4MiB”提示调查、对局日志面板、弹窗按钮布局、双方状态栏及回放状态的专项回归。
- [ ] 使用正式卡池构建干净发布包，检查卡图及其他资源完整；在单机、联机和回放中验证版本一致、规则结果一致，且旧回放只在已验证兼容的规则版本下播放。
- [ ] 任何仍处于“待定”的卡牌或规则边界不得标记为完整实装；发布说明中列出未纳入内容及其原因。

# 美术资源接入规范

版本 `ui_art_v1`。本文件描述资源绘制合同，客户端尚未使用新 UI PNG；卡牌插画按现有 `runtime.json` 加载。设计示例来自真实卡牌定义，但为人工构造的展示状态，不能直接作为规则重放输入。

## 布局和采样

逻辑画布 1600×1000。保持当前客户端等比缩放与留边，不拉伸到不同窗口比例；纹理关闭平滑，使用最近邻采样。所有坐标在逻辑画布中取整；原生 UI 像素单位 1。32×32 图标也提供精确 2 倍的 64×64 版。

| 元素 | 基准坐标 / 尺寸 | 约定 |
|---|---|---|
| 本方手牌 | 260,862 / 1080×134 | 水平滚动，卡牌 101×118；数量独立显示 |
| 对手手牌 | 顶部中央 | 使用 39×41 卡背，只传递公开张数 |
| 阵法槽 | 260,560+55×i / 106×52，i=0..4 | 阵体 2 合并为 106×107；不能误解为额外环位 |
| 解析行 | 373,560+55×i / 427×52 | 跟随宿主行，超宽内容水平滚动 |
| 施法区 | 260,487 / 1080×65 | 无固定槽上限 |
| 言灵区 | 809,560 / 531×106 | 最多三张来自核心规则 |
| 行动区 | 809,674 / 531×49 | 结算区，没有每回合次数槽 |
| 灰烬区 | 809,731 / 531×101 | 可滚动 |

对手场地区域使用当前公式 `(1600-x-w, 960-y-h, w, h)`；不旋转标签或卡牌文字。HUD、手牌和详情沿用各自位置，不套用该公式。

## 分层与伸缩

绘制顺序：`match_background` → `board_decoration` → 区域框/空槽/宿主连线 → 卡框 → 插画 → 动态文字、类型和稀有度 → 实例状态 → 操作高亮 → 操作条/提示 → 决策/终局/换手遮挡。

`ui/manifest.json` 中 `insets` 均为 `[left, top, right, bottom]`，单位为源 PNG 像素。九宫格保留四角，边缘仅沿对应方向拉伸，中间区域可伸缩。背景保持等比画布；卡背/插画等比包含，不裁切主体。没有 `stretch` 声明的图标和装饰按固定尺寸绘制。锚点默认为左上 `[0,0]`，图标中心锚点在清单中给出。

- 卡框边饰切分 8px；文字与规则区重新布局，不能把字随纹理拉伸。带内部横线的卡框优先按原生规格使用，竖版需变高时单独重排横线和底栏。
- 按钮切分 12/8/12/8；文字边距 14/7/14/7；按下文字向下偏移 1px。
- 区域框切分 8/22/8/8，顶部 22px 保留标签槽；标签为动态文字。
- 带标题面板切分 12/40/12/12；反馈面板左侧 44px 保留图标。
- 宿主连接线和跨槽括号可由源代码按实际宿主范围绘制。不能简单把二槽纹理当成单槽重复。
- 流程稿中的纹理缩放用于展示位置。实际九宫格实现应读取清单，不能直接整张非等比拉伸。

## 卡牌信息区

手牌标题区位于 `(11,6)`，字号 11；主体区 `(5,24,w-10,h-56)`，等比缩放完整透明图；位阶为主体右上独立角标；底部两行分别为费用与类型，稀有度在右下。解析/施法费用分段，不相加展示。更小窗口由整体逻辑画布缩放，不能继续压缩中文字体。

短卡条左侧 29px 留给缩略图，卡名位于 `(34,5)`，状态位于 `(34,24)`。缩短高度时重新对齐第二行，不能照搬 44px 模板坐标导致溢出。附着符文角标独立命中区域，最小逻辑 22×23；点击显示符文详情及其合法拆除操作。

详情内部：标题 y=10，类型/稀有度 y=35，插画 y=53..147，费用 y=164，属性 y=185，目标 y=201，规则 y=218，实例 y=287，支付摘要 y=320。内边距 12px。当前 13 张规则按 12px 字体、16px 行高展示；未来更长文本应在规则阅读区滚动或扩展阅读层，不能以省略号隐藏唯一规则全文。费用摘要保留两行，超长目标/弃牌摘要放到独立 `summary` 面板或顶部任务提示，不能挤入执行按钮。

状态包括解析中、解析完成、待施放、持续生效、准备被取消、基础保护和符文附着。准备被取消后法术仍在解析区，本次施法荷载清零、解析荷载保留、魔素和额外弃牌不退，本回合不能再次准备。普通 UI 取消没有这些规则效果。

类型使用图标、文字和左侧色带；稀有度使用独立宝石数量和文字：白 1 / 绿 2 / 青 3，预留紫 4 / 金 5。稀有度不染整个操作边框。

## 操作和遮挡

操作条宽度按按钮数计算，优先置于源卡上方，相隔 8px；顶部不足则置于下方。右界不得越过 1340，左界不小于 260，与右侧详情分开。不可覆盖当前待点击目标；目标/额外成本步骤隐藏执行条并保留顶部取消入口。多操作时使用操作条内部水平滚动和左右箭头，不生成屏外按钮。

同一卡牌叠加优先级：正常 < 悬停 < 源卡选中 < 目标候选 < 目标已选 < 额外成本候选 < 额外成本已选。源卡青绿内侧角标始终保留；目标以断续边框/菱形表达，成本以紫色折角/勾表达，不只靠颜色。目标高亮与成本高亮在各自步骤互斥。类型和稀有度标记不被高亮替代。

四个步骤为查看、目标、额外成本、确认。无目标或成本时跳过；只显示核心提供的合法操作，不凭设计稿增加执行入口。确认摘要明确源卡、动作、宿主/目标、弃牌、本次魔素和新增荷载；玩家目标只写自己/对手，不增加头像点击步骤。确认提交前不能扣资源。

`flows.json` 覆盖 13 组流程：查看、阵法、解析、准备、行动、言灵、符文、施法选择、结束弃牌、临时荷载、触发/超额、取消和终局。六类决策复用 `decision`：响应、施放顺序、触发顺序、结束弃牌、临时荷载移除、多余法术移除。选项过多在容器内滚动；剩余数量、可否跳过必须读取当前决策。候选在弹窗内直接列出，不要求玩家点击被弹窗挡住的场内卡牌。

换手时停止绘制私有手牌、详情、操作条、日志和提示，再绘制不透明接手面板。公开场地仍显示。不能仅靠一个半透明遮罩遮住私有信息。胜/负/平局有独立标记；荷载等于容量不显示失败，严格超过才按核心结果显示过载。

## 文件与验收边界

PNG、SVG 与代码源同时交付；SVG 的图片引用是相对路径，保留 `assets/art` 目录树。SVG 文字为可编辑文本，依赖项目中文字体，不包含字体轮廓副本。

文件校验包括 13 张透明 PNG、四张旧图 SHA-256 不变、190 张 UI 的尺寸/固定色板/二值 alpha/无文字节点、46 张设计稿尺寸和 SVG 链接。全卡池详情、复杂场地、额外成本确认和换手稿进行了图像查看。真人可读性、各种窗口比例、九宫格接入以及完整交互回归，在 UI 皮肤代码接入后验收，不以设计稿文件检查代替。

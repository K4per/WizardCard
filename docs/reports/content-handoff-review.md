# 内容侧对接与文档矛盾核对报告

日期：2026-10-07。核对对象：用户提供的《09-与K4per对接清单》《10-文档矛盾确认表》。基线为已同步远程的 Alpha v1.0：程序 `1.0.0-alpha`、规则/卡池 `1.0.0`。

这两份材料作为待核对的意见与问题清单，不替代用户已经确认的规则，也不自动授权更换负责人、恢复交付门槛、改许可证或发布外部下载。以下区分实现事实、历史变更、文档问题与未决定事项。

## 结论

内容侧推进、数值参照扩充及文档收敛的方向合理。当前自动验收证明本地游戏流程和规则稳定性，不能证明真人体验或策略平衡。仓库的真人试玩表未填写，因此只能确认**没有入库的试玩证据**，不能凭此断言实际从未试玩。

正式写卡基线已经明确：生命40/40、火球术10点火焰伤害、治疗上限40、火花术为零阶言灵、同名最多3张、主卡组30张、基础资格2种、九套预设、卡池30种。详见[全卡图鉴](../card-catalog.md)。两份材料中大部分数值差异来自历史版本；少数现行指南仍有漏改，已在本次修订。

《矛盾确认表》按编号统计为 **33项**：A17项、B8项、C5项、D3项；不是概述中的30项。下表全部逐项回答。判定“有意变更”也包含合法能力差异与历史基线，不表示每一处都要改引擎；“笔误”包含当前文档的过期口径。

## 3. 三种取消字段的准确边界

| 字段 | 目标与效果 | 来源/支付/清理 |
|---|---|---|
| `cancel` | 取消指定准备根节点；银光锐语使用此效果 | 不退款；按准备取消收尾释放本次追加施法荷载、保留解析完成，标记自己的本回合不能重试。卡牌主效果不自动赋予任意时点。 |
| `negate_link` | 标记一个合法、未结算且未取消的链节；按该链节种类执行取消收尾 | 不额外附带法术销毁与反制者延迟荷载。现有核心/夹具有能力，不等于每张正式卡都有它。 |
| `counter_spell` | 无效对手待释放法术链节，并销毁来源法术 | 按目标实际施法费用快照给反制者次回合临时荷载；来源离场关联清理。正式法术反制4速，之后不允许追加响应。 |

玩家可用“取消准备”“取消链节”“法术反制”三个术语。`kind`是程序效果接口，卡名是内容名称，二者不能为追求表面统一而合并。

## 4. 对内容推进建议的评估

**卡池数学应修正。** 30张、同名最多3意味着一副合法主卡组至少需要10个不同名称，不意味着固定恰好10种；也可用15种各2张等分配。因此“每副牌固定吃卡池1/3”只能描述目前多份预设的选牌方式。池子小会限制差异化与冗余替代，但单凭30这个数字不能证明五方向各2–3条联动“不可能”，也不能证明100种必需。应先画每方向的核心组件、替代件、泛用接口和反制路线，再决定卡数。

**批次与接入粒度可分开。** 文档建议一批设计12–15张，可以作为内容提案；工程接入仍按2–4张可验证小批次执行。两者不必冲突。现有“到100种需18–35批”的算术成立，但目标100种与大批量定稿权都还未获用户确认。复用effect kind也不代表所有新目标条件、时点组合和动态计算都无需引擎修改。

**内容并行合理，联网目标仍保留。** 网络对战不会自动解决数值或乐趣，但能让不同设备的玩家实际对抗，不能断言对体验零贡献。建议把内容路线设计/试玩组织与网络无窗口阶段并行，卡牌接口变更先写规范和回归，再进核心。v1.5原有目标与顺序没有因这两份材料被自动改写。

**真人试玩有必要，恢复门槛需重新决定。** 用户已经取消本次Alpha20局门槛，不能追溯性把已交付Alpha判为未完成。可以为后续内容平衡提出新试玩批次，记录卡池版本、重复卡使用率、卡手、荷载败北、对局长度与具体体验；是否恢复20局及何时形成门槛待用户决定。

## 5. 平台与许可的事实边界

当前承诺为Windows x64本地客户端，v1.5先做局域网两人对抗；Linux目标是无窗口核心CI，不等同Linux图形客户端发行。仓库没有macOS/Android/iOS客户端构建预设或触屏适配验收；这表示**未交付**，不能凭此认定C++或SFML必然不能用于移动端。

手机若纳入范围，需要设计触摸替代右键/滚轮、响应式布局、键盘输入与打包/生命周期测试。也不能说“所有输入层都必须重写”：当前合法动作、规则提交、AI和复盘可继续复用，界面已有共享按钮/文本/资源和交互模型。是否保持现有表现层或另选前端，需在手机承诺、设备与工作量明确后再比较，当前不批准迁移。中文文本输入与固定逻辑画布缩放已有代码；完整IME组合与设备DPI能力不能据此假定全部验收。

许可方面，仓库有MIT总LICENSE，音频有用户明确的CC0记录，插画/Logo/图标有来源记录；美术缺少独立、明确的授权范围说明。这是需澄清的发布问题，不能仅凭“provenance不是许可”断言总MIT必然不涵盖美术，也不能未经确认改成CC BY或保留全部权利。须由用户明确美术/UI/Logo范围及可授权权利，之后再写资产LICENSE。TCG称谓是否保留是产品表述决策；当前未实现收藏获取、交易或开包，事实可以明确，名称不因本文自动更改。

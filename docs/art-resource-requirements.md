## 3. 当前13种卡牌插画需求

以下构图是初步建议，整体画风已定为像素风，具体像素密度仍在试制。画面突出规则功能，费用、伤害数值、卡名、稀有度及规则文字由程序叠加，避免后续平衡调整重画。

| 卡牌ID | 中文名 | 展示类型 / 当前稀有度 | 建议画面主体与辨识要求 |
|---|---|---|---|
| `balance` | 均衡 | 阵法 / 普通 | 用户修订为有设计感的六芒星（类似大卫之星），两枚三角交织、六点均衡装饰；首批新版无背景；基础身份使用独立UI标识 |
| `fireball` | 火球术 | 解析法术 / 稀有 | 聚集后释放的大型火球；明确的核心与方向；规模和轮廓区别于火花术 |
| `barbs` | 银光锐语 | 言灵 / 罕见 | 银色锐利咒文，按反馈简化为清晰的少量锐笔符号，无环境背景；表达打断准备，避免画成夺取或摧毁法术 |
| `recall` | 奥术回想 | 行动 / 普通 | 从记忆或卷页中召回奥术知识；表现抽取知识，区别于清心的减压 |
| `ring` | 奥术圆环 | 符文 / 普通 | 单枚清晰圆环，正面、对称纹样，中心镂空，无环境背景；既适合阵法也适合法术宿主；另可派生附着小标识 |
| `spark` | 火花术 | 解析法术 / 普通 | 小型、集中的火焰火花；轮廓简洁，不能只是火球术缩小复制 |
| `mend` | 生命缝合 | 解析法术 / 普通 | 光线缝合受损生命之核；表现修复生命，区别于恢复魔素 |
| `unravel` | 结构瓦解 | 解析法术 / 稀有 | 空闲扩展阵法的几何结构崩解；突出阵法破坏，区别于直接玩家伤害 |
| `disrupt` | 魔力扰动 | 行动 / 罕见 | 外来波纹扰乱魔力结构，使负担增加；不使用魔素偷取或治疗的视觉语义 |
| `clarity` | 清心 | 行动 / 普通 | 消散杂乱能量、恢复精神清明；表现移除临时负担，不暗示所有法术荷载均被清空 |
| `reservoir` | 蓄能阵 | 阵法 / 普通 | 容器式、收束型阵图；强调承载空间，区别于导流阵的流动与收入 |
| `conduit` | 导流阵 | 阵法 / 罕见 | 导管式阵图汇聚能量；强调魔素流入；与蓄能阵保持不同结构 |
| `ward` | 炽燃结界 | 解析法术 / 罕见 | 持续燃烧的攻击性结界；体现持续伤害，避免用护盾主体暗示防御效果 |

范围校验：行动3种、解析法术5种、言灵1种、阵法3种、符文1种，共13种。牌库中的12种卡组成30张测试卡组；均衡作为额外基础阵法，仍需要插画。

建议先做均衡、火球术、银光锐语、奥术圆环4张样稿，覆盖阵法、主动法术、响应与附着机制；确认一致性后补齐其余9张。

## 4. 信息表达的关键约束

1. **魔素与荷载分开。** 使用不同轮廓和图标，不仅用颜色；当前荷载等于上限仍安全，严格超过才过载。临界状态可以预警，不能误画成已败北。
2. **法术状态可读。** 解析中、解析完成、待施放、持续生效必须清楚区分；持续法术保留荷载并显示剩余计数。准备被取消不等于法术销毁。
3. **阵法与宿主关系可读。** 法术承载、符文附着和基础阵法保护分别表达。首版每宿主一张符文，不设计多符文叠层。
4. **额度与场上卡分开。** 行动区每回合3次、咒文区3槽、解析区5个阵法槽。阵体会占多个阵法槽，环位另计；施法区不画成固定数量槽位。
5. **交互服从合法操作。** 目标高亮来自核心校验。现在不合法的操作通常不出现在操作列表；禁用样式仅用于后续确实展示的不可用组件。
6. **私有信息遮挡。** 换手时公开区域仍可看，私有手牌、操作和日志不得因头像、动画、缩略图或提示框泄露。
7. **稀有度有辅助标签。** 当前卡池只用普通白、罕见绿、稀有青；规范预留史诗紫、传说金。暂不制作高稀有度专属装饰。

## 5. 建议交付规格与程序接入

以下是开始制作前的建议规格，最终须经过界面样稿确认；现有代码没有定义正式卡面比例。

| 资源 | 建议源文件与导出 | 接入注意事项 |
|---|---|---|
| UI图标 | 可编辑像素源；透明PNG，至少64与128像素版本 | 在24–32逻辑像素下检查；最近邻采样，严格像素版本应使用二值透明度 |
| 卡牌插画 | 分层源文件；无文字PNG；建议先统一1024×768、4:3插画窗口 | 这是插画窗口建议，不是整张卡牌比例；预留中心裁切安全区，不直接塞进现有小卡条 |
| 详情框/面板/按钮 | 分层像素源；需要贴图时透明PNG及边距说明 | 优先可伸缩结构；边缘保持整数像素；由程序绘制的组件交付规范与状态稿即可 |
| 背景 | 源文件与PNG；建议1600×1000，保持16:10 | 上下双方区域与右侧操作面板须有低对比留白；窗口缩放维持现有逻辑视图 |
| 角色头像 | 可编辑源与透明PNG；建议512×512 | 双方共用同一角色，仅用玩家标识区分 |
| 特效 | 优先动画参数与效果稿；若用序列帧，PNG图集附帧尺寸、顺序、帧率和锚点 | 现有动画仅为0.45秒通用提示线，需另行事件绑定和绘制实现 |

建议路径（尚未接入，不能仅复制文件就生效）：

```text
assets/art/cards/<card_id>.png
assets/art/ui/icons/<semantic_name>.png
assets/art/ui/...
assets/art/backgrounds/match.png
assets/art/portraits/apprentice.png
assets/art/effects/...
```

程序接入任务：建立卡牌ID与插画的映射；为现有卡条和详情面板增加适当的缩略图/插画区域；绑定状态、数值和宿主标识；增加组件与背景绘制；确保缺失美术仍可回退至文字原型。不得把资源文件字段或目录约定描述为现有功能。

每批素材附资产ID、文件名、源文件位置、尺寸、透明度、作者/来源、许可与制作版本。新增第三方素材的许可与发布包一同保存。

## 6. 建议制作顺序与验收

1. **先做可读性规范。** 用对局界面稿核对资源、状态、目标、宿主关系和换手遮挡；沿用已授权中文字体。画风未定，可先延续当前深色底与青绿色强调色验证布局。
2. **交付P0基础组件并接入。** 验收初始对局、言灵响应换手、临时荷载选择、结束弃牌、终局等场景；检查中文与缩放、滚动后选中状态、私有信息遮挡。
3. **确认4张插画样稿，再补齐13幅。** 全部用卡牌ID命名；制作可复用详情框。数值和规则文字维持动态显示。
4. **真人探索后润色。** 根据实际辨识障碍增加背景、头像或特效；卡池改变时同步调整清单，不为尚未实现的机制提前量产。

验收状态使用：待设计 → 待制作 → 待接入 → 待验收 → 已验收。已有文件不等于已接入；已有截图不等于真人界面验收完成。

## 7. 暂缓范围与待定项

暂缓：卡包商城、抽卡动画、收藏册、复杂角色技能、多套主题、多人场地、联网大厅、隐藏咒文专用背面、多符文叠层、额外卡池与高稀有度豪华卡框。现阶段没有相应已实现功能需求。

已确定：用户指定像素风、奇幻风格 UI。首批试制采用深靛石板、古铜框饰与青绿符文，属于制作方提出的方向，尚未记为用户验收。

待确定：具体像素密度与限色方案、插画与详情框最终比例、是否调整对局布局、预算与交付节奏。

音频为单独需求：代码已经尝试播放可选的 `assets/audio/confirm.wav`，当前未发现该文件。若后续整理音效需求，可先补确认音，再评估抽牌、伤害、换手与终局反馈；不计入本美术资产数量。

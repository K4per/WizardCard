# Windows 对局交互验收

2026-11-21 实测。基线采用 696a464 的 2.6.4 对局页、正式卡池与同版 Windows 原生桥接。复测采用热修订工作树的对局页、机制修订 13 卡池和重建的 Windows DLL。两次均运行 Godot 4.7.2 Windows 原生窗口，使用同一张 RTX 4070 Laptop GPU 的 OpenGL Compatibility 渲染。鼠标和键盘输入经窗口视口分发；测试时点模式也使用选项控件的 item_selected 信号。

## B01 猜拳

- 旧版挑战 AI 第一轮，手势为 -1，revision 1。点击忽略时点后选择面板消失；Esc 也没有恢复手势。见 [旧版画面](baseline-opening.png) 和 [旧版状态](baseline-opening-and-captions.json)。
- 修复后，在同一未提交轮次选择手势，再点击“取消操作”会清空暂选并重新显示全部三种手势，revision 保持不变。切换三种时点或按 Esc 均可继续选择。挑战 AI 进入首回合；本地换手双方先平局，第二轮分别选择石头、剪刀，双方各抽五张并完成初始阵法。见 [新版画面](opening-ignore-ai.png) 和 [逐轮记录](verified.json)。

## B02 维持专注

- 旧版挑战 AI，种子 42。通过原生合法动作完成设置、施法与回位；单人调试功能供给特定卡、昂扬符文和魔素。在准备阶段确认提示、点击高亮卡、点击“收起”、按 Esc，再点“展开选择”。点击维持并确认后仍停在原决定。匕首之云 #103 的决定 134、revision 143、魔素 1 保持不变；避火咒 #104 的决定 75、revision 228、魔素 2 同样不变。此时窗口保留候选，底层动作查询已经取消。[旧版卡死画面](baseline-daggers.png) · [决定与余额](baseline-upkeep-esc.json)
- 旧版直接点卡并确认则能够支付。另复现两处可观察异常：关闭详情会清掉来源高亮，维持按钮显示卡名而省略维持金额。[直接支付对照](baseline-opening-and-captions.json)
- 修复后从场地点击同一实例，关闭详情和切换时点保留选择。收起后按 Esc 立即重新展开有效选择。可见维持按钮显示原生报价；每例仅产生一次维持事件，未新增荷载，并继续到主要阶段。[新版选项](v260-analytic-0013-choice.png) · [每项原生结果](verified.json)

## O01、O02 响应与确认

- 在 Windows 对局页注入连续两个空响应窗口、一个有合法来源的窗口，记录真实控件和发送时机。全时点弹 3 次、自动放弃 0 次；可用时点弹 1 次、自动放弃 2 次；忽略时点弹 0 次、自动放弃 3 次。每批 3 个决定各提交一次。查看场面、取消已暂存动作均保留该时点。[计数](verified.json)
- 连锁询问与确认动作使用同一窗口；在 1280×720、1920×1080 拖动标题至四角并缩放，整窗和按钮都在视口内，刷新同一决定保留位置。键盘确认和取消各触发一次，过期窗口不能提交。[720p 连锁询问](response-dialog-1280.png) · [1080p 动作确认](action-dialog-1920.png)
- 另在原生 AI 对局设置匕首之云 #103，动作弹窗显示基础法阵 #9、第 1 环、设置费用 2。Esc 后牌仍在手中，revision 不变；再次确认后魔素从 16 到 14，卡落在所选环位。[原生报价画面](native-setting-quote.png)

自动回归入口为 [hotfix_interactions.gd](../../../godot/tests/hotfix_interactions.gd)。脚本从正式卡表启动对局。使用窗口运行时传入 `--output <目录>` 可重新生成截图和 JSON；CTest 的 `godot_hotfix_interactions` 运行相同输入和断言。

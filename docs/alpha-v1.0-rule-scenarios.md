# Alpha-v1.0 规则演算与回归场景

> **历史0.3.0夹具，不能用于当前写卡数值。** 本页20生命、火球术6伤害、银光锐语4费用及手牌响应保留旧测试预期。正式1.0.0为生命40/40、火球术10伤害、银光锐语设置5，禁止手牌响应；请以[卡池图鉴](card-catalog.md)、[正式卡池](../assets/cards.json)与[新规则规范](alpha-v1-cards.md)为设计入口。

日期：2026-10-05。依据：[规则设计0.3.0-draft.1](alpha-v1.0-rules.md)。

以下是规则0.3.0的演算及回归依据。S1～S4已在 `tests/chain.cpp` 落实，配合既有规则及交互测试验证；真实构建、客户端与重放结果见[阶段二报告](reports/alpha-v1.0-stage2.md)。测试占位能力仅在测试catalog或忽略的构建目录中使用，不写入正式 `assets/cards.json`，不计入五种方向卡池。

## 1. 演算约定

双方使用基础均衡，容量各8；初始生命各20。每个示例是独立局面，已完成当前阶段的开始窗口。例中L1、L2、L3为链节别名，测试应使用引擎实际分配的全局ID。阶段标记窗口与未提及的窗口均无响应候选，双方自动放弃。魔素与荷载全部为非负整数；额外符文或成功释放奖励未配置。

施法准备和实际释放是两条不同连锁。每条构建期间都需要双方连续放弃才开始结算；例中说“通过”即完成这一过程，不能直接调用效果结算器冒充响应协议。

## 2. S1：普通准备与实际释放

局面：A自己的第2回合主要阶段，魔素2，火球术已解析完成，解析荷载3；B没有响应能力。双方生命20。

| 步骤 | A魔素 | A荷载/上限 | B生命 | 必须观察的状态 |
|---|---:|---:|---:|---|
| 宣告前 | 2 | 3/8 | 20 | 火球术在阵法上，占一个环位 |
| A准备火球术，创建L1 | 1 | 4/8 | 20 | 支付施法1；仍在阵法上；首次优先权给B |
| B、A通过，L1成功 | 1 | 4/8 | 20 | 移入施法区，待施放；原环位释放；没有伤害 |
| 结束主要阶段并进入施法阶段 | 1 | 4/8 | 20 | 玩家选择火球术，创建新的释放根节点 |
| 释放窗口双方通过并结算 | 1 | 0/8 | 14 | 造成6伤害，火球术离场，移除全部4荷载 |

断言：进入施法阶段不再次支付施法费；准备成功不是成功释放；完成释放之后才可推进到结束阶段。

## 3. S2：银光锐语取消准备

局面：A第2回合主要阶段，魔素2，火球术解析荷载3；B魔素1，已预置银光锐语，预置绑定荷载4。预置费早已支付，例中不再扣。

| 步骤 | A魔素/荷载 | B魔素/荷载 | 链节及结果 |
|---|---|---|---|
| A宣告准备 | 1 / 4 | 1 / 4 | L1为火球术准备，B取得优先权 |
| B发动预置银光锐语 | 1 / 4 | 1 / 4 | L2指向L1，银光锐语移入结算区；A取得优先权 |
| A、B通过 | 1 / 4 | 1 / 4 | 构建关闭，先结算L2 |
| L2结算并收尾 | 1 / 4 | 1 / 0 | L1标记取消；银光锐语离场；检查状态 |
| 轮到L1执行取消收尾 | 1 / 3 | 1 / 0 | 火球术保留解析完成，释放本次追加1荷载，不退魔素 |

断言：本回合再次准备同一火球术拒绝，且魔素/荷载不变；下一次自己的回合可重试。取消标记不会提前把火球术销毁或释放原解析3荷载。

## 4. S3：手牌反反制恢复准备

局面：A第2回合主要阶段，魔素3，火球术解析荷载3；B魔素1，预置银光锐语占4荷载。A持有测试行动卡 `fixture_negate`：只在测试catalog声明从手牌响应 `prepare` 窗口，费用1、无负担，效果为取消指定尚未结算链节。

| 步骤 | A魔素/荷载 | B魔素/荷载 | 链节及结果 |
|---|---|---|---|
| A准备火球术 | 2 / 4 | 1 / 4 | L1，优先权给B |
| B发动银光锐语 | 2 / 4 | 1 / 4 | L2指向L1，优先权给A |
| A从手牌发动测试响应 | 1 / 4 | 1 / 4 | L3指向L2；公开测试卡，支付1，优先权给B |
| B、A通过 | 1 / 4 | 1 / 4 | 构建结束 |
| L3结算 | 1 / 4 | 1 / 4 | L2标记取消，测试卡离场；费用不产生自动荷载 |
| L2执行取消收尾 | 1 / 4 | 1 / 0 | 银光锐语离场，不能取消L1，预置费不退 |
| L1成功 | 1 / 4 | 1 / 0 | 火球术进入施法区，原环位释放 |
| 施法阶段释放通过并结算 | 1 / 0 | 1 / 0 | B生命20→14，火球术离场 |

断言：实际顺序L3→L2收尾→L1；银光锐语的已取消效果不执行。测试卡离场后没有可再次响应的候选。A共付2魔素，不把行动响应费算成火球术荷载。

## 5. S4：上层响应导致过载，停止下层减压

局面：A自己的主要阶段，魔素2、容量8，火球术解析荷载3、持续炽燃结界绑定荷载3、临时荷载2，总荷载8。A手持清心。B魔素2，测试catalog为魔力扰动声明手牌响应 `action` 的占位能力：费用2、无自身负担，对对手增加2临时荷载。正式魔力扰动不因本设计稿获得此能力。

| 步骤 | A魔素/荷载/容量 | B魔素 | 结果 |
|---|---|---:|---|
| A宣告清心 | 1 / 8 / 8 | 2 | 清心无使用负担；创建L1，准备清除最多2临时荷载 |
| B宣告测试版扰动响应 | 1 / 8 / 8 | 0 | L2，支付2；尚未向A加荷载 |
| A、B通过 | 1 / 8 / 8 | 0 | 构建结束 |
| L2结算并收尾 | 1 / 10 / 8 | 0 | A增加2临时荷载；B响应卡离场；状态检查判A过载败北 |
| 终局 | 1 / 10 / 8 | 0 | L1不结算，清心未清除荷载；不发生后续阶段/触发 |

断言：判负发生在L2完整结算和清理后，不等待L1。终局清空活动连锁与决策，但不补做清心离场；清心的实体终局快照仍位于行动区。不能把“之后本可减压”作为免除当前过载的理由。

## 6. 阶段2回归矩阵

下列编号是验收场景，不与CTest用例一一对应；一个测试可能覆盖多个场景，历史测试也继续覆盖继承规则。阶段2新增拒绝场景比较完整规范状态与摘要，确保包括ID计数在内不变。客户端自动推进与换手遮挡由真实重放及截图补充验证；Linux结果仍待远程CI。

### 阶段与优先权

| 编号 | 场景 | 验收断言 |
|---|---|---|
| PH-01 | 一个无牌可用的完整回合 | 五阶段事件依序出现，每阶段开始/结束窗口各一次；空阶段未省略 |
| PH-02 | 先手首回合与后手首回合 | 仅先手基础抽牌跳过，双方准备收入正常，抽卡阶段响应时点仍存在 |
| PH-03 | 准备阶段已有阵法、新阵法和解析法术 | 收入→解析推进→准备触发→开始窗口；新阵法不补发收入，解析完成不直接施放 |
| PH-04 | 施法区仍有待施放法术时推进 | 推进拒绝；持续生效法术不进入待施放选择；主体不提供普通主要操作 |
| PH-05 | 空阶段自动通过开/关 | 同样的核心规则；开启由客户端提交推进，关闭等待；主要阶段始终显式结束 |
| PH-06 | 阶段结束窗口内响应 | 响应和产生的触发先完成；之后只执行一次阶段收尾，不能提前进入下一阶段 |
| PH-07 | 结束窗口抽牌、持续到期触发再抽牌 | 先窗口再清理；持续只减1，必要时再次弃至8张；窗口不重复开放 |
| CH-01 | 放弃一次后对手追加响应 | 计数归零，原放弃者重新取得机会；两次连续放弃才结算 |
| CH-02 | 某方无合法候选 | 该方自动放弃，不越过另一方合法响应；事件不带私有候选数量或拒绝原因 |
| CH-03 | 至少三层响应，目标为较早链节 | 可指向合法的非紧邻链节；按逆序处理，不增加速度等级要求 |
| CH-04 | 同一卡牌实例重复响应 | 第二次拒绝，不重复扣费或占位；同名不同实例可分别发动 |
| CH-05 | 过期/错误玩家/另一连锁的目标ID | 原子拒绝，包括窗口ID、优先权、链节和分配计数均不变 |
| CH-06 | 连锁结算中提交响应或普通操作 | 拒绝；强制清理选择仍可完成当前链节，不另开窗口 |
| CH-07 | 一方仍有合法响应但选择放弃 | 允许放弃，不替该方擅自使用卡牌；重新交付优先权使用新决策ID |

### 费用、取消和生命周期

| 编号 | 场景 | 验收断言 |
|---|---|---|
| LC-01 | S1、S2、S3、S4 | 逐步资源、区域、优先权和终局结果与上述表格一致 |
| LC-02 | 宣告会恰好达到/超过容量、来源作自身弃牌成本 | 等于允许，超过及自弃成本拒绝；不能依靠未来减压支付；拒绝不消耗额外成本 |
| LC-03 | 无响应声明的普通手牌 | 各窗口均无手牌发动权限；银光锐语默认仅预置发动 |
| LC-04 | 手持响应言灵支付与被取消 | 只支付声明的手牌费用，等量绑定荷载直到离场；不重复预置/发动费 |
| LC-05 | 对手回合的响应临时负担 | 在承担者下个自己的结束清理到期；来源进入灰烬后仍存在 |
| LC-06 | 取消准备后的下回合重试 | 首次施法费不退，仅移除本次追加荷载；下一尝试支付记录独立 |
| LC-07 | 上层销毁响应来源 | 已入链快照通常继续；明确依赖来源存在的能力失效；荷载不重复清除 |
| LC-08 | 上层销毁准备法术的源阵法 | 完成关联离场；准备根节点失效，不恢复已离场法术 |
| LC-09 | 已成功准备后源阵法被销毁 | 施法区法术不随旧阵法离场，荷载和符文继续跟随法术 |
| LC-10 | 必需目标全部失效或部分失效 | 全失效正常收尾、无奖励；多目标只处理合法部分，不重新选目标 |
| LC-11 | 取消实际释放、持续触发或行动 | 分别离场释放绑定荷载、仅跳过单次触发、保留行动临时负担；均不默认退款 |
| LC-12 | 含伤害后治疗的同一链节 | 不在语句之间提前判负；该链节清理后才检查，保持0.2.3粒度 |

### 触发、清理和胜负

| 编号 | 场景 | 验收断言 |
|---|---|---|
| ST-01 | 销毁阵法及其承载法术 | 全部关联离场后计算荷载/容量；避免只降容量就判负 |
| ST-02 | 破坏空闲扩展均衡，容量16→8，荷载10不变 | 关联清理后过载败北；基础均衡不可作为破坏目标 |
| ST-03 | 强制环位缩减需要多项选择 | 全部选择和关联清理完成才检查；不能借选择插入主动响应 |
| ST-04 | 多人同事件触发及链内新触发 | 回合方排序后非回合方排序，逐项独立根节点；新触发追加尾部，不打断当前连锁 |
| ST-05 | 奥术圆环附着瞬时/持续法术 | 仅首次成功释放返还该次实付施法费，受12上限；失效/取消不返还，后续触发不重复 |
| ST-06 | 抽多张中途失败，随后同项效果补回牌库 | 抽牌失败记录保留，项末状态检查判负 |
| ST-07 | 同次检查双方败北与上层单方败北 | 分别平局或另一方获胜；剩余链节/触发/阶段停止 |
| ST-08 | 可停止循环、不可停止重复逻辑状态 | 前者等待合法决策，后者平局；递增ID/日志不妨碍逻辑循环识别 |

### 基础阵法、投影和复盘

| 编号 | 场景 | 验收断言 |
|---|---|---|
| CF-01 | 未标资格、非阵法标资格、未知基础ID | 非资格阵法不能开局，非阵法资格定义拒绝；错误不静默回退 |
| CF-02 | 两方不同合法基础阵法 | 开局各自公开设置并占阵体，各自收入/容量/环位/位阶正确 |
| CF-03 | 基础均衡及主牌库同名3张 | 卡组合法；仅基础实例受保护，普通扩展副本可离场 |
| CF-04 | 基础阵法容量、环位或最高位阶为0 | 基础资格定义拒绝；收入0仍允许 |
| IV-01 | 双方手牌和不同手牌响应能力 | 投影只给本人私有卡与响应候选；公开链节在宣告后向双方可见 |
| IV-02 | 当前优先权持有者变化/换手遮挡 | 新查看者投影正确，旧UI未提交选择清空，旧决策ID拒绝 |
| RP-01 | 不同主牌库/基础阵法开局并完整重放 | 格式2记录实际双方配置，逐条摘要及最终结果一致 |
| RP-02 | 任意活动连锁、结算中强制选择及结束清理快照 | 同版本跨配置/跨平台规范摘要相同，阶段子步和清理一次性标记被计入 |
| RP-03 | 修改目标、支付结果、内容版本或基线格式1记录 | 被篡改记录检测分歧；不兼容版本/格式明确拒绝 |

## 7. 实施与验证顺序

1. 先实现基础配置和阶段子步，转为PH/CF场景，保留原有资源与状态回归。
2. 实现根节点、优先权、双放弃、结算区和逆序，落地S1/S2与CH场景。
3. 实现显式手牌响应和取消链节，落地S3/S4与LC/ST场景；测试占位留在测试代码。
4. 同步投影、命令编码、复盘格式及无窗口驱动，执行IV/RP场景。
5. 更新换手客户端选择模型，执行点击与拖放完整重放；Windows核心/客户端和Linux核心CI分别记录真实结果。

阶段1只执行文档检查。阶段2已落实核心、内容、交互和实际客户端重放；逐组测试对应及尚未执行的跨平台验证见[实施报告](reports/alpha-v1.0-stage2.md)。

## A · 古籍金饰

```text
Use case: ui-mockup. Create a polished LANDSCAPE visual direction review board for WizardCard, a new FULLY 2D fantasy card game frontend. ONE image with THREE clearly separated game-screen panels: a large 16:9 COMPLEX BATTLE screen occupying the top two thirds; two smaller 16:9 screens beneath side by side, MAIN MENU left, DECK BUILDER right. Three screens must share one coherent design system; crisp readable composition, not a scrapbook. Small outer heading identifies variant. Flat orthographic 2D UI, not a perspective 3D table, not an open-book double-page layout.
Images 1,2,3 are existing pixel card illustrations: orange fireball, jeweled six-point formation star, arcane ring. Use these recognizably in several sample card faces and large selected-card detail. Keep pixel character and motifs; do not turn into realistic paintings. All surrounding frames/buttons/backgrounds are NEW designs, no copying old card frame. Preserve compatibility with these pixel illustrations.
Battle screen: opposing player areas TOP and BOTTOM, low-contrast quiet middle; ONLY three main zone categories labelled Chinese “解析区”, “施法区”, “灰烬区”. Analysis contains face-up resolving spell and generic face-down anonymous cards; casting rows have variable slots grouped beneath formation hosts, not fixed five formation slots. Several formation host groups with clear thin association lines. A main deck stack and separately labelled formation side-deck entrance on each player's side. Opponent hand backs at top, player's face-up fan hand at bottom, no revealing opponent face-down identity. Left separate READ-ONLY card details showing fireball with rarity gem, type/level, speed icon and readable short rules. Right slim chain panel with C1,C2,C3 and reverse arrow C3→C2→C1, speed badge 1-4 and separate log. Separate compact bottom-right action/confirm strip “确认” and “取消”, not controls inside card details. HUD for each player: actual life heart, distinct temporary shield layer with expiry, mana crystal, load meter and cap. Show example load 6/8 with separate warning legend normal/overload/danger rather than arbitrary immediate death. Five-phase strip “抽牌 / 准备 / 主要 / 施法 / 结束”, current priority and pass “放弃响应”. Small formation recipe preview with 2 condition rows and action quota 1/1. Icon callouts for face-down 0 cost, flip cost, next-turn talisman waiting, speed4 “不可响应”. No action zone, no separate incantation zone, no separate face-down zone, no shop.
Menu: brand text exactly “WizardCard”, buttons “本地对局”, “AI对局”, “真人联机”, “卡组构筑”, “设置”, “退出”, clean primary emphasis, subtle thematic background.
Deck builder: left detail card with recipe space, middle separate list containers titled “主卡组 40/40” and “阵法副卡组 10/10”, right card pool grid using pixel references; top five filter tabs “解析 / 咒符 / 言灵 / 阵法 / 符文”, clear save button.
Text is review mockup only. Prefer a few short correctly spelled Chinese labels and large readable numerals instead of dense faux writing; leave extra body fields clean. Ornaments only at edges; no large characters obscuring interface, no full-screen glows. Strong consistent hierarchy, card illustrations vivid and text panels quiet. Opaque background. STYLE DIRECTION: Antique gilded spellbook fantasy, finely illustrated 2D materials with burgundy leather, dark warm walnut, antique gold narrow filigree and warm ivory reading panels, emerald accents. Restrained ornamental geometry, sophisticated medieval archive. Warm tactile richness but no photoreal 3D depth. Card illustrations stay pixel art, UI framing slightly finer illustrated treatment.
```

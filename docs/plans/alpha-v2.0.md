# Alpha v2.0 迭代路线

2026-10-10 启动。依据组内改动报告与本轮确认，交付保留 C++ 内核的 Godot 2D Windows x64 客户端，恢复换手、三档 AI、教学、构筑、设置、复盘和 LAN 对战。内核先行，Godot 桥接和基础控件同期准备。

规则唯一入口为 [新规则规格](../alpha-v2.0-rules.md)，当前规格标识 `alpha-v2-final-2026-10-10`；最终报告及本轮解释优先于旧计划中的冲突条款，差异见 [最终规则同步](../reports/alpha-v2.0-final-rule-sync.md)。模块职责及接口为 [模块化说明](../alpha-v2.0-architecture.md)，内容审定入口为 [30卡迁移草案](../proposals/alpha-v2/review.md)。历史 v1.5 和 2.5D 方案保留为记录，本路线取代其实施顺序、视觉与旧规则假设。

## 三条工作线与依赖

- 工程：共同类型 → 内容/复盘拆分 → 会话接口与适配 → 分层构建/CI。
- 规则：迁移草案审定与引擎夹具并行；基础规则 → 时点/阶段 → AI/教学 → 正式内容。
- 前端：工具链/桥接 → 通用控件 → 本地页面 → LAN 页面 → 演出/独立导出。
- 前端完整玩法集成依赖完整规则；正式卡池及预设依赖组内审定；发行依赖两机和真人输入验收。

任务采用 GitHub Issues，三条工作线在标题标记；未审定内容与真人验收使用 ready-for-human，规格完备且依赖已满足的工程任务使用 ready-for-agent。计划中的待发布任务及依赖见 [任务清单](alpha-v2.0-tasks.md)。

## 版本与兼容

纯工程拆分保持程序 1.1.0-alpha、规则/卡池 1.0.0、复盘2和协议1，用旧记录验证行为。切换新规则时使用 2.0 草案标识，卡组存储2、复盘3和协议2；最终规则/卡池固定2.0.0。

旧用户卡组保留原件和未知 ID，导入待修复草稿，不自动补齐40+10。新版拒绝旧规则复盘，由保留的旧发行包读取。资源不进入规则内容哈希。

## 交付约束

使用 dev 集成、master 保存已验收版本，保留现有未提交资料及 snapshot/v1.5-25d-art。每个阶段归档构建标识、测试与复盘，自动测试不能代替两台实体 Windows 和真人 IME/DPI/声音验收。平衡持续记录五方向，不设固定局数门槛。

首个平台 Windows x64；Linux 继续验证无窗口核心及跨平台复盘。移动端、公网匹配/中继、账号、观战、主机迁移、完整召唤系统和完整1–7级卡池另行规划。未确定人员投入前不承诺日历工期。
